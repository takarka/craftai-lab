# CraftAI Lab (`Builder`)

Мобильное приложение и серверная платформа для создания, настройки и безопасного использования учебных ИИ-агентов преподавателями.

> **Статус репозитория:** в репозитории размещён исходный код стадии MVP (ветка `feat/prd-0.2-mobile-mvp`). Подробная инструкция локального запуска разработчика также находится в [HOW_TO_RUN.md](HOW_TO_RUN.md).

---

## 1. Паспорт проекта

- **Название проекта и автор:** CraftAI Lab (`Builder`); автор: **Turganbekov Anarbek**.
- **Направление:** **Startup_ecosystem**.
- **Проблема и конкретный пользователь:** учитель (преподаватель), которому нужен управляемый ИИ-ассистент под конкретный предмет и класс (например, подготовка заданий или проверка ответов) без потери контроля над инструкциями, учебными материалами, памятью и действиями агента.
- **Основной сценарий:** учитель создаёт изолированного агента (выбирает модель, задаёт задачу, предмет, класс, инструкцию, скиллы и разрешения на работу с материалами) → приложение отправляет запрос в среду выполнения с учётом правил платформы, инструкции, скиллов и подтверждений → пользователь получает структурированный учебный результат (с возможностью подтвердить или отклонить запись материала и проверить трассу «Как выполнено»).
- **Форма продукта:** мобильное приложение на Flutter (`3.47.7`, целевые платформы Android и iOS; для локальной разработки и деморежима поддерживается Web/Chrome) и автономный backend на Python (`3.12+`, FastAPI, SQLAlchemy, SQLite/PostgreSQL, интеграция с OpenRouter API).
- **AI-инструменты и вклад:**
  - **Личный вклад автора и развитие проекта для конкурса:** постановка задачи и требований к учебному ИИ-конструктору, проектирование архитектуры мульти-агентности (переход от одного ассистента к 5 изолированным агентам), удаление лишних модулей (календарь, расписания, генерация DOCX/PDF), проектирование и реализация серверного контракта `/lab/v1` (агенты, версии конфигураций, запуски, harness с лимитами, подтверждения, MCP «Материалы»), клиентского экрана «Мои агенты» и локального деморежима, а также код-ревью и тестирование.
  - **Использованные при разработке AI-инструменты:** Claude Code (модели Claude Sonnet 5.5 и Claude Opus 5.5) — генерация и рефакторинг кода Flutter-клиента и backend, написание тестов, подготовка документации и релизной сборки; соавторство отмечено в истории коммитов (`Co-Authored-By`). Архитектурные решения, постановка требований, код-ревью и проверка результата выполнены автором.
  - **Сторонние материалы:** открытые библиотеки Flutter и Python (см. раздел 7), шрифты Onest и JetBrains Mono (SIL OFL); учебные примеры и тексты интерфейса подготовлены автором.
- **Условия запуска:**
  - **Для быстрого деморежима (без сервера):** устройство с ПК-браузером Chrome, Flutter `3.47.7`, доступ к интернету при первом скачивании пакетов (`flutter pub get`).
  - **Для полного запуска с сервером:** Flutter `3.47.7`, Python `3.12+`, Chrome (для Web) или Android SDK + JDK 17 (для сборки Android APK) / macOS + Xcode (для iOS), база SQLite (по умолчанию) или PostgreSQL 16 (через Docker).
  - **Внешние сервисы и расходы:** для вызова реальных LLM требуется ключ OpenRouter API и указание двух моделей в настройках сервера (возможны расходы по тарифам OpenRouter). Деморежим (`main_demo.dart`) и работа с черновиками агентов на сервере без вызова моделей работают бесплатно.
- **Данные и ограничения:**
  - **Данные и хранение:** учётная запись, конфигурации и версии агентов, учебные материалы (текст до 10 000 знаков), фото (JPEG/PNG до 10 МБ, по архитектуре — с удалением исходника через 24 часа после извлечения текста), память агента и диалоги. На мобильных устройствах кэш SQLite шифруется через `StorageCipher` с ключом в системном хранилище; на сервере данные хранятся в SQLite или PostgreSQL.
  - **Что работает:** очистка кода от лишних модулей (LM00), серверное управление агентами/версиями/прогрессом (LM01), серверный runtime/harness с подтверждениями и лимитами (LM02), MCP «Материалы», фото/OCR, память и скиллы (LM03), клиентский список «Мои агенты», мастер создания и кэш (LM04), экраны диалога `/agents/:agentId/chat`, настроек и трассы «Как выполнено» (LM05), 7-урочный курс и аналитика без текстов (LM06), а также локальный шаблонный деморежим (`lib/main_demo.dart`).
  - **Что не реализовано или имитируется:** в деморежиме (`lib/main_demo.dart`) ответы имитируются шаблонами без вызова реальных моделей, а фото/OCR, SSE и курс в деморежим не входят. Для работы реальных моделей в основном приложении требуется запущенный `backend/` с настроенным ключом OpenRouter API.

## 3. Запуск приложения

### Сценарий для проверяющего (из workspace)

> Готовая Android-сборка доступна в GitHub Release v0.1.0 (ссылка в шаге 2).

1. Откройте [Startup_ecosystem - ChatGPT](https://chatgpt.com/spaces/page_space_47402f4174b081a4a784f9b0bd53c4bb?view=overview).
2. Перейдите по ссылке на репозиторий или скачайте сборку: [craftai-lab-0.1.0-arm64.apk](https://github.com/takarka/craftai-lab/releases/download/v0.1.0/craftai-lab-0.1.0-arm64.apk) (GitHub Release [v0.1.0](https://github.com/takarka/craftai-lab/releases/tag/v0.1.0)).
3. Установите приложение на устройство (или откройте веб-версию по ссылке выше) и запустите **Craftai Lab**.
4. Выполните вход с тестовой учётной записью (см. раздел 5) и пройдите стартовый онбординг, если он отображается.
5. На главном экране **«Мои агенты»** откройте существующего агента или создайте нового (лимит — 5 агентов).
6. Задайте параметры агента (название, предмет, класс, инструкция) и сохраните изменения.
7. Откройте диалог с агентом (в деморежиме — кнопка **«Открыть» → «Открыть демодиалог»**) и отправьте учебный запрос.
8. При запросе на запись данных (например, «Сохрани материал») подтвердите или отклоните действие в карточке подтверждения.
9. Откройте экран **«Как выполнено»**, чтобы проверить шаги выполнения и ограничения.

### Сборка и запуск из исходного кода (для разработчика)

#### Вариант А: быстрый деморежим без сервера и API-ключей (Chrome)

```powershell
Set-Location Builder
flutter pub get --enforce-lockfile
flutter run -t lib/main_demo.dart -d chrome --web-hostname 127.0.0.1 --web-port 8080
```

Откроется `http://127.0.0.1:8080` с баннером деморежима и шаблонными ответами (точка входа `lib/main_demo.dart` работает только в debug/dev-режиме).

#### Вариант Б: полный локальный запуск (`backend/` + `Builder/`)

1. **Сервер (`backend/`, Python 3.12+):**
   ```powershell
   Set-Location backend
   py -3.12 -m venv .venv
   & ./.venv/Scripts/python.exe -m pip install -e .
   if (-not (Test-Path .env)) { Copy-Item .env.example .env }
   & ./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 5001 --reload
   ```
   Проверка готовности API: `http://127.0.0.1:5001/health`.
2. **Клиент (`Builder/`, Flutter 3.47.7):**
   - Запуск в Chrome против локального сервера:
     ```powershell
     Set-Location Builder
     flutter pub get --enforce-lockfile
     flutter run -d chrome --web-hostname 127.0.0.1 --web-port 8080 --dart-define=APP_ENV=dev --dart-define=CRAFTAI_API_BASE_URL=http://127.0.0.1:5001
     ```
   - Сборка release APK (как в [CI](.github/workflows/builder-ci.yml), требуется Android SDK и JDK 17):
     ```powershell
     Set-Location Builder
     flutter pub get --enforce-lockfile
     flutter build apk --release --target-platform android-arm64 --dart-define=APP_ENV=staging --dart-define=CRAFTAI_API_BASE_URL=<URL_СЕРВЕРА>
     ```

## 5. Доступ для проверяющего

- **Разрешения приложения:**
  - В текущей конфигурации (`AndroidManifest.xml` и `Info.plist`) используются только сетевые разрешения (`INTERNET`, `ACCESS_NETWORK_STATE`).
  - Разрешения камеры и галереи для сценария фото/OCR предусмотрены в архитектуре приложения, но в манифесты ещё не добавлены.
- **Аккаунты и подписки:**
  - В деморежиме (`lib/main_demo.dart`) аккаунт, сервер и подписки **не требуются**.
  - При запуске с локальным сервером `backend/` при старте автоматически создаётся локальный аккаунт разработчика (учётные данные описаны в [HOW_TO_RUN.md](HOW_TO_RUN.md) и [backend/README.md](backend/README.md); публичный стенд не развёрнут, поэтому отдельного тестового аккаунта нет: проверяющий использует деморежим без входа или локальный backend с автоматически создаваемым аккаунтом разработчика).
  - Подписка на платные сервисы не обязательна для проверки интерфейса и серверного CRUD, но для реальных ответов моделей через OpenRouter требуется платный или пробный баланс API-провайдера.
- **Переменные окружения (без значений и секретов):**
  - **Клиент (`Builder/`, передаются через `--dart-define`):**
    - `APP_ENV` — окружение сборки (`dev`, `staging`, `prod`).
    - `CRAFTAI_API_BASE_URL` — базовый URL backend API (например, для локального HTTP-сервера).
  - **Сервер (`backend/.env`, шаблон в [backend/.env.example](backend/.env.example)):**
    - `CRAFTAI_ENV` — режим окружения сервера.
    - `CRAFTAI_DATABASE_URL` — строка подключения к БД (SQLite или PostgreSQL).
    - `CRAFTAI_STORAGE_DIR` — каталог для хранения загруженных файлов.
    - `CRAFTAI_JWT_SECRET` — секрет для подписи JWT-токенов доступа.
    - `CRAFTAI_OPENROUTER_API_KEY` — ключ доступа к OpenRouter API для запуска моделей.
    - `CRAFTAI_OPENROUTER_BASE_URL` — базовый URL OpenRouter API.
    - `CRAFTAI_LAB_MODEL_1_ID`, `CRAFTAI_LAB_MODEL_2_ID` — идентификаторы двух моделей в каталоге Lab.
    - `CRAFTAI_LAB_MODEL_1_SUPPORTS_TOOLS`, `CRAFTAI_LAB_MODEL_1_SUPPORTS_VISION`, `CRAFTAI_LAB_MODEL_2_SUPPORTS_TOOLS`, `CRAFTAI_LAB_MODEL_2_SUPPORTS_VISION` — флаги совместимости моделей с инструментами и изображениями.
    - `CRAFTAI_ENABLE_EMBEDDED_WORKER` — включение фонового обработчика очистки истёкших ресурсов.

## 6. Практическая польза и адаптация

- **Подтверждённые результаты на текущий момент:**
  - Подтверждено прохождение модульных, виджет- и контрактных автотестов по всем фазам (LM00–LM07, `pytest`: 37 passed, `flutter analyze`: 0 issues) и успешная сборка и запуск на устройстве `Redmi Note 9 Pro` (зафиксировано в [журнале проверок](docs/plans/01-prd-0-2-mobile-mvp-progress.md)).
- **Предполагаемая практическая польза (требует пилотной проверки):**
  - Учитель может разделять задачи по отдельным изолированным агентам (до 5 на аккаунт), не смешивая материалы, память и инструкции разных классов и предметов.
  - Явное подтверждение записи материалов, лимиты выполнения и экран «Как выполнено» позволяют контролировать действия ИИ-агента в учебном процессе.
- **Адаптация для другой образовательной организации:**
  - Достаточно развернуть свой экземпляр `backend/` со своими ключами моделей (`CRAFTAI_LAB_MODEL_*`) и пересобрать клиент `Builder/` с нужным `CRAFTAI_API_BASE_URL`. Все агенты, инструкции, скиллы и материалы привязаны к `owner_id` и изолированы на уровне базы данных.
