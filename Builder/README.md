# Craft Builder

Самостоятельное Flutter-приложение экосистемы CraftAI. Учитель проходит курс и собирает ИИ-ассистента. Начата реализация приложения: bootstrap, конфигурация, защищённые маршруты и RU/KK. Добавлены формы входа, регистрации и запроса восстановления пароля. Настоящий вход CraftAI ещё не подключён: отправка форм отключена с явным уведомлением. UI Kit доступен отдельным DEV-входом. Зависимостей от `mobile` нет.

## Запуск

Проверено на Flutter 3.47.7 / Dart 3.13.5. Минимум текущих зависимостей: Flutter 3.44 / Dart 3.12; native minimum OS ещё уточняется в F01.

```sh
cd Builder
flutter pub get
flutter run -d chrome --dart-define=APP_ENV=dev
```

Также сохранены отдельные проекты Android и iOS с идентификатором `com.example.builder`. Для сборки Android нужны Android SDK и JDK 17; для iOS — macOS и Xcode. Перед публикацией замените пример идентификатора и настройте подпись.

Публичная конфигурация: `APP_ENV=dev|staging|prod` (по умолчанию `prod`), `CRAFTAI_API_BASE_URL=https://…` — только base URL CraftAI, без ключей/query/fragment. До подключения API URL можно не задавать: приложение не подставляет вымышленный сервер и не отправляет запросы. HTTP допускается только для loopback в dev. Даже при заданном URL реальная авторизация ещё не реализована.

```sh
flutter run --dart-define=APP_ENV=staging --dart-define=CRAFTAI_API_BASE_URL=https://your-craftai-host/api
```

На Linux с установленным Chromium можно задать `CHROME_EXECUTABLE=/usr/bin/chromium` перед `flutter run -d chrome`. Android требует Android SDK, iOS — macOS/Xcode; успешный web preview не заменяет их проверки.

## UI Kit

Каталог запускается отдельно; `main.dart` его не импортирует. В release DEV-вход отклоняется.

```sh
flutter run -t lib/main_gallery.dart -d chrome
```

Четыре раздела: основы, контролы, композиции и персонаж. Переключатели, поля, чипы, состояния сообщений, подтверждения и выбор модулей можно проверить прямо в каталоге. Каталог не отправляет запросы к модели и не создаёт события в календаре.

- `lib/app/` — bootstrap, окружения, router, ARB/RU/KK и временные страницы каркаса.
- `lib/features/auth/` — формы, валидация, controller и порт подключения настоящего auth API.
- `lib/core/errors/` — безопасные типизированные ошибки.
- `lib/features/session/` — интерфейс сессии без имитации рабочего входа.
- `lib/core/platform/` — платформенные возможности, отдельно от OS permissions.
- `lib/ui_kit/` — переиспользуемые токены, тема, иконки, компоненты.
- `lib/gallery/` — примеры использования компонентов.
- `assets/` — локальные шрифты с лицензиями, оригинальные SVG-иконки и персонаж.
- `docs/ui-kit.md` — API, соответствие макетам, состояния, решения по доступности.
- `test/` — адаптивность и поведение интерактивных компонентов.

```sh
flutter analyze
flutter test
flutter build web --release
```

## Аккаунт: текущая готовность

Маршруты `/sign-in`, `/register`, `/recover-password` доступны без сессии. Условия и политика открываются поверх текущего экрана в root navigator (`/legal/terms`, `/legal/privacy`). До подключения B01 и защищённой сессии F03/F04 стандартный `NotConnectedAuthGateway` отключает отправку: форма не создаёт аккаунт, не отправляет письмо и не имитирует успешный вход.

Регистрация требует опубликованных документов с непустыми текстами и revisions для выбранного языка. Согласие привязано к языку и обеим revisions, не отмечено заранее. Юридические тексты не сочинены: сейчас их отсутствие показано явно. Пароль не сохраняется в состоянии Riverpod/на диске/в логах; очищается после попытки, при переходе и уходе приложения в фон. Очистка поля не является гарантией обнуления immutable-строк в памяти Dart.

Mobile auth использует только `/mobile/auth/*`: documents, register, login, refresh, logout, forgot-password, reset-password и change-password. Access token живёт только в памяти процесса; refresh token и его expiry хранятся только через защищённое OS storage. Refresh отправляет JSON `{ "refreshToken": "…" }`, всегда заменяет refresh token и выполняется single-flight; неуспешный refresh очищает локальную сессию.

## Онбординг S01–S03

Добавлены знакомство с Builder, поиск предмета/«Другое», классы 1–11 с групповыми кнопками, отдельный язык ассистента (RU/KK/оба), сводка и имя. Маршруты `/onboarding`, `/onboarding/preferences`, `/onboarding/assistant` доступны только аккаунту, которому требуется онбординг.

Черновик существует только в памяти текущего аккаунта. Он сохраняется между шагами, очищается при смене аккаунта/выходе и теряется после закрытия приложения. Создание в основном приложении отключено до подключения проверенного постоянного хранилища F03; защищённое хранение этим интерфейсом не имитируется.

Отдельный DEV-предпросмотр не требует backend:

```sh
flutter run -t lib/main_onboarding_preview.dart -d chrome
```

Он использует явно обозначенный preview-аккаунт и запись только в память. Постоянная DEV-плашка сообщает об этом; release-запуск отклоняется. `main.dart` не импортирует preview-адаптеры и не получает обход входа. После создания в preview открывается существующая оболочка трёх вкладок; чат и уроки ещё не подключены.

В рамках этапа F03 реализовано постоянное защищённое хранилище (`lib/core/storage/`):
- Реляционная схема V1 на 18 таблиц с каскадным удалением и изоляцией владельцев.
- Аппаратное хранение ключей (`SecureKeyStorage` / Keystore / Keychain) и аутентифицированное шифрование (`StorageCipher`).
- Атомарный двухфазный файловый журнал (`FileStagingJournal`) с автоочисткой при старте.
- Изоляция сессий, сброс кэшей при смене пользователя и защита поколениями `workspaceEpoch` (`WorkspaceStorageService`).
- `PersistentInitialWorkspaceRepository` для атомарной, идемпотентной инициализации пространства без перезаписи.
- Защита базы от скрытого удаления при сбоях (`deleteDatabase` запрещён, поднимается `StorageCorruptionException`).
