## QA-001 — JSON вместо названий в «Последних чатах»

Статус: открыт, сообщено пользователем и независимо подтверждено через ADB. Причина пока не подтверждена.
Серьёзность: средняя (нарушено отображение списка чатов).
Окружение: Builder 0.1.0 (1), Redmi Note 9 Pro, 2026-10-20. Соответствие установленной сборки текущим исходникам не установлено.

### Предусловия и шаги

1. Использовать сохранённую авторизованную сессию с существующими чатами.
2. Открыть Builder и экран ассистента.
3. Посмотреть первые элементы раздела «Последние чаты».

Ожидается: понятные текстовые названия чатов.
Фактически: по сообщению тестировщика названия первых чатов отображаются как JSON. При открытии проблемного чата JSON виден и внутри него; история сообщений отображается нормально. Независимая проверка подтвердила JSON именно в заголовке; тело запроса навыка отображается читаемо.
Контроль нового разговора: после отправки «Объясни дроби для 5 класса простыми словами» появилось такое же читаемое название без JSON. При этом старые чаты продолжают показывать JSON. В этой проверке дефект наблюдается у существующих чатов; причина и поведение других новых чатов пока не установлены.
Подтверждены минимум два названия в последних чатах; начало значения: {"builder_skill_request":1,…}. Общий охват и частота пока не установлены.

### Задача

Проверить путь получения, сохранения и отображения названия чата; определить, откуда приходит структурированное содержимое. Исправить установленную причину и обработать уже сохранённые некорректные названия, если это необходимо, без потери истории.

Критерии приёмки:
- Последние чаты показывают читаемые названия без сырого JSON.
- Обычные текстовые названия продолжают отображаться корректно.
- Некорректное структурированное значение не ломает список; предусмотрено понятное резервное название.
- Открытие чатов сохраняет историю; результат проверен на затронутых существующих чатах и новом чате.

Доказательства: сообщение тестировщика и независимая проверка через ADB. [recent-chats.png](2026-10-20/recent-chats.png) — два названия начинаются с `{"builder_skill_request":1,"task…`; [TC-006-history-ready.png](2026-10-20/TC-006-history-ready.png) — JSON также в списке истории; [QA-001-old-chat.png](2026-10-20/QA-001-old-chat.png) — JSON в заголовке открытого старого чата, при этом запрос навыка в теле отображается читаемо («Навык: Создать проверочную»).

Уточнение для диагностики: затронутый проверенный чат создан запуском навыка. Не следует считать возраст чата причиной: обычный новый чат и разговор из навыка используют разные исходные данные. В текущем коде `chat_providers.dart` название формируется из первого пользовательского содержимого, а список показывает `conversation.title` напрямую; это направление расследования, не подтверждённая причина установленной сборки.

## QA-003 — Чат не прокручивается до конца после отправки и ответа

Статус: открыт. Сообщено тестировщиком; через ADB подтверждено, что после отправки и появления ответа конец разговора остаётся за пределами экрана.
Серьёзность: средняя — для чтения нового ответа нужна ручная прокрутка.
Окружение: установленный Builder 0.1.0 (1), Redmi Note 9 Pro.

### Воспроизведение

1. Открыть длинный чат про дроби, находясь у конца предыдущего ответа.
2. Ввести `Show a short example of 1/2`.
3. Нажать отправку и дождаться ответа.

Ожидается: после отправки новое сообщение видно, а при поступлении ответа чат следует за его концом, если пользователь не прокрутил историю вверх вручную.
Фактически: после появления ответа экран показывает конец старого ответа, новое сообщение и начало нового ответа. Нижняя часть нового ответа вне экрана. Сразу после нажатия сделан также промежуточный снимок во время скрытия клавиатуры; он сам по себе не используется как доказательство устойчивого дефекта.

Доказательства: [input-screen.png](2026-10-20/input-screen.png) — введённый текст; [QA-003-settled.png](2026-10-20/QA-003-settled.png) — состояние после ответа. [QA-003-after-send.png](2026-10-20/QA-003-after-send.png) — промежуточное состояние. [QA-003-before-send.png](2026-10-20/QA-003-before-send.png) — исходный вид до успешного ввода.

### Задача и критерии приёмки

Проверить автопрокрутку при добавлении сообщения, потоковом увеличении ответа и изменении доступной высоты из-за клавиатуры. После собственной отправки показывать актуальный конец разговора. Во время ответа следовать вниз, пока пользователь сам не перешёл к старым сообщениям; не мешать чтению истории принудительными скачками. Проверить длинный ответ, открытую/закрытую клавиатуру и повторную отправку.

Точная причина и соответствие исходников установленной сборке пока не установлены.
