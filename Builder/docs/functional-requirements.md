# Craft Builder — функциональные требования

Версия 0.2 (черновик) · 16.10.2026. Изменения 0.3: MVP — уровни 1–5; только облако через OpenRouter, три категории моделей (мощная, рабочая, быстрая), локальные модели убраны; состояние ассистента хранится на телефоне; бэкенд-прокси CraftAI; инструменты уровня 5 уточнены. Ранее: отдельное приложение экосистемы CraftAI, вход по e-mail и паролю, персонаж ассистента, вкладка «Ассистент» вместо отдельного чата, один общий сброс, без сертификата

Документ описывает, что должен делать Craft Builder — отдельное мобильное приложение экосистемы CraftAI, где учитель собирает ИИ-ассистента и изучает, как он устроен. Требования выведены из концепции и кликабельного прототипа (16 экранов). Приоритеты и состав MVP — предложение для согласования с заказчиком.

## 1. Введение

### 1.1 Цель и границы

Цель: дать учителю безопасную практическую среду, где он на 9 уровнях (в первой версии доступны 1–5) развивает своего ассистента и понимает принципы работы ИИ.

В границах версии: прохождение уровней, чат с ассистентом, версии и сброс, режим «под капотом», выбор категории модели (мощная, рабочая, быстрая), сравнение моделей, подключения (MCP), профиль и прогресс, управление контентом.

За границами (предложение): тарифы и учёт расходов на модели, совместная работа нескольких учителей над одним ассистентом, публикация ассистентов для учеников, веб-версия, сертификат, собственный сервер моделей в Казахстане, перенос ассистента между устройствами, вход через Google и Apple, несколько форм персонажа.

### 1.2 Роли

| Роль | Описание | Основные действия |
| --- | --- | --- |
| Учитель | Основной пользователь | Проходит уровни, настраивает ассистента, общается с ним, сравнивает модели |
| Редактор контента | Готовит материалы курса | Создаёт и публикует уроки, тесты, пояснения «под капотом» |
| Администратор платформы | Отвечает за модели и серверы | Ведёт модели трёх категорий (мощная, рабочая, быстрая), подключения MCP, мониторинг |
| Методист школы (предложение) | Сопровождает группу учителей | Смотрит прогресс группы; доступ к содержимому чатов — открытый вопрос |

Внешние системы: OpenRouter (облачные модели), поиск в интернете, демонстрационный MCP-сервер CraftAI; позже — сервис распознавания речи и собственный сервер моделей.

### 1.3 Термины

| Термин | Значение |
| --- | --- |
| Ассистент | ИИ-помощник, которого учитель собирает и улучшает |
| Уровень | Этап курса, добавляющий ассистенту одну возможность (всего 9; в первой версии доступны 1–5) |
| Версия | Сохранённое состояние ассистента, к которому можно вернуться |
| Сброс | Общий сброс «Начать заново»: ассистент — к чистой модели, курс — к уровню 1 |
| Рентген | Режим «под капотом»: что передано модели, что вернулось, что выполнило приложение |
| Категория модели | Какая модель отвечает: мощная, рабочая (по умолчанию) или быстрая, все через OpenRouter; модели на телефоне и собственный сервер в Казахстане — в следующих версиях |
| MCP | Стандарт подключения внешних сервисов к ИИ (список возможностей и вызов действий) |
| Коннектор | Конкретное подключение по MCP: в первой версии — демонстрационный каталог уроков CraftAI; позже календарь, диск |

### 1.4 Соглашения

- Идентификатор: FR-<модуль>-<номер>.
- Приоритет: M — обязательно, S — желательно, C — возможно позже.
- MVP: да/нет. В MVP предложены уровни 1–5.
- Источник: экран прототипа, если есть.

### 8.1 Основные сущности

Все сущности, кроме аккаунта пользователя CraftAI, хранятся на телефоне и не передаются на сервер.

| Сущность | Ключевые поля |
| --- | --- |

| Документ знаний | название, статус (вкл / выкл), фрагменты для поиска |
| Факт памяти | текст, источник, дата |
| Подключение MCP | коннектор, разрешения, статус |

### 8.2 Интеграции

| Интеграция | Назначение | Примечание |
| --- | --- | --- |
| Шлюз моделей (с совместимым API) | Бэкенд-прокси CraftAI: проверка аккаунта, вызов OpenRouter, ключ хранится на бэкенде, список разрешённых моделей, учёт токенов без текстов | Список моделей меняется без обновления приложения |

| MCP-серверы | Демонстрационный коннектор CraftAI (каталог уроков); позже календарь, диск, журнал | Вход в сторонние сервисы — через их авторизацию |
| Платформа CraftAI | Аккаунт, вход, общая админ-панель | Общий аккаунт CraftAI, вход по e-mail и паролю |

## 9. MVP и критерии приёмки

Предлагается первой версией выпустить уровни 1–5 с общими обучающими функциями; уровни 6–9 — следующая очередь.

| В MVP | Не в MVP |
| --- | --- |
| Уровни 1–5: инструкции, знания, память, инструменты (включая демо-MCP) | Уровни 6–9: голос, зрение, безопасность (отдельный уровень), агент |
| Облако через OpenRouter, три категории моделей (мощная, рабочая, быстрая) | Модели на телефоне, собственный сервер в Казахстане, кабинет методиста, бейджи, несколько форм персонажа |
| MCP: демонстрационный коннектор CraftAI (каталог уроков) | Календарь и диск Google, электронный журнал, голосовой ответ |
| Под капотом, сравнение моделей, версии и сброс, профиль | Аналитика прохождения, гибкое добавление коннекторов без обновления |

Критерии приёмки:

| Область | Критерий |
| --- | --- |
| Основной цикл | Новый пользователь проходит путь «знакомство → первый ответ → под капотом» без подсказок вне приложения |
| Версии | Восстановление версии возвращает инструкции, знания, инструменты и категорию модели; после сброса ассистент пуст |
| Знания | Вопрос с ответом в документе показывает найденный фрагмент; без ответа — предупреждение о риске выдумки |
| Инструменты | Действие с последствиями не выполняется без подтверждения (проверяется тестом) |
| MCP | После отключения подключения ассистент не вызывает сервис (проверяется по журналу вызовов) |
| Данные | У каждого ответа есть метка места обработки; запросы к модели идут только через бэкенд CraftAI; приложение не обращается к OpenRouter напрямую |
| Голос | (После MVP, уровень 6) Расшифровка видна и редактируется до отправки модели |
| Локализация | Все экраны MVP доступны на русском и казахском |

## 10. Допущения и открытые вопросы

Допущения:

- Прототип — иллюстрация, а не финальный дизайн; расшифровки и ответы в нём — демо-данные.

- Расходы на модели на этом этапе не учитываются; пилот на первом этапе проводится на устройстве автора, покупатель не определён.
