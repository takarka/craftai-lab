# F00. Уточнить границы, решения и готовность к разработке

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B00: опубликованные схемы и границы данных. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Цель:** получить один согласованный baseline, исключающий противоречивую реализацию.

- [x] F00-01. Зафиксировать baseline FR/NFR, flow, макетов и текущего кода; выделить изменения после него.
- [ ] F00-02. Принять таблицу приоритетов M0/M1/P2 и отдельный список после MVP.
- [ ] F00-03. Закрыть ADR-01/02/03 о версиях, физическом удалении и учебном draft.
- [ ] F00-04. Разделить согласия D02/D03, разрешения инструмента и OS permission; определить сроки и повторное подтверждение.
- [ ] F00-05. Утвердить все недостающие экраны/состояния из раздела 8.
- [ ] F00-06. Назначить владельцев Flutter, контента RU/KK, дизайна, проверки устройств и мобильного выпуска; получить контакт владельца B00 как внешнюю зависимость.
- [ ] F00-07. Определить комплект тестовых материалов без персональных данных: PDF/DOCX/TXT, календарь, аккаунты, каталог уроков.
- [x] F00-08. Разделить критичные неизвестные, которые блокируют код, и решения, которые можно уточнить в ходе пилота.

**Артефакты:** утверждённый scope, журнал ADR, актуальная матрица экранов и условий приёмки.

**Выход:** для каждой критичной неоднозначности есть решение или явно обозначенный блокируемый этап. Код функций с неопределённой семантикой не начинается.

- [ ] F00-V01. Зафиксировать решения по визуальному аудиту раздела 1.5: полный snapshot против «версий инструкции», девять уровней против агрегированного блока, группы классов, предел имени, XLSX и отсутствующие состояния. Не менять FR по демонстрационным примерам.
