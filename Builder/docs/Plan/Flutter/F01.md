# F01. Проверить технические риски на устройствах

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B03 только для проверки живого облачного потока; локальные spikes не ждут сервер. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F00; результаты нужны до выбора постоянного storage/RAG/OS stack.

- [ ] F01-01. Поднять существующий Builder на реальном Android и iPhone, не только в браузере.
- [ ] F01-02. Зафиксировать минимальные ОС после проверки актуальных требований Flutter, embedding runtime и плагинов. Не назначать версии ОС по предположению.
- [ ] F01-03. Проверить защищённую БД, ключи, миграции, backup exclusion и переустановку.
- [ ] F01-04. Проверить extract текста PDF/DOCX/TXT с кириллицей, казахским, таблицами и повреждёнными файлами.
- [ ] F01-05. На среднем Android и iPhone измерить локальную embedding-модель и поиск: время, RAM, размер, нагрев, потребление батареи.
- [ ] F01-06. Проверить FTS/vector index и поведение при отмене/удалении во время индексации.
- [ ] F01-07. Проверить native-календарь: чтение, доступные календари, создание, отказы и идентификацию уже созданного события.
- [ ] F01-08. Проверить системную подготовку звонка/SMS, отмену, отсутствие обработчика и различия результатов iOS/Android.
- [ ] F01-09. Проверить Flutter-декодер на контрактных fixtures; после готовности B03 отдельно проверить живой поток CraftAI, stop, usage и передачу native-результата. Сервер здесь не разрабатывать.
- [ ] F01-10. Проверить клиентский сценарий RU/KK на опубликованных B02/B03 моделях; дефекты серверной конфигурации оформить входящими задачами B02, не исправлять в этом этапе.

**Артефакты:** короткий technical feasibility report и решения по библиотекам; измерения привязаны к устройству/сборке.

**Выход:** критичный сценарий «локальный документ → найденный фрагмент → реальный облачный ответ с trace» технически подтверждён. Если нет — пересмотр ADR-07 до разработки S41; переход на облачные embeddings не выполняется молча.
