# F09. Настройки ассистента, версии, восстановление и общий сброс

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** нет; версии и общий сброс локальны. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F03/F07/F08, закрытые ADR-01/02/10.

- [x] F09-01. Реализовать S11 со схемой/персонажем и доменными состояниями восьми умений; 6–9 остаются «Скоро».
- [x] F09-02. Реализовать S14 и сохранение имени, не добавляя несколько обликов персонажа.
- [x] F09-03. Создать единый `CommitAssistantChange`, который сохраняет конфигурацию и новую версию с human-readable причиной.
- [x] F09-04. Для свободного текста использовать draft + явное сохранение; не создавать версии на каждый символ или перестроение виджета.
- [x] F09-05. Поддержать ручное сохранение и автоматическое сохранение по завершению уровня/изменению настроек.
- [x] F09-06. Реализовать S12, отметку текущей, номера/даты/причины, одну исходную версию и отсутствующие ресурсы.
- [x] F09-07. Реализовать D04: предварительная сводка, сохранение прежнего состояния и корректное восстановление без side effects.
- [x] F09-08. Предотвратить обход course capabilities через snapshot старой/более высокой версии.
- [x] F09-09. Реализовать S15: карта локальных данных, предупреждение о потере при переустановке, политики хранения, один D05.
- [x] F09-10. Реализовать сильное подтверждение D05, отмену in-flight задач, epoch fence, транзакцию и recoverable file cleanup.
- [x] F09-11. Сделать одну реализацию сброса, вызываемую из S15/S11 и меню S20; не дублировать логику в экранах.
- [x] F09-12. Поддержать «Отменить изменение» через согласованную операцию версии, без удаления истории и без повтора внешних вызовов.
- [x] F09-13. После D05 перейти в S03 к базовому ассистенту, как на листе Flow; не повторять регистрацию и выбор аккаунта. Повтор D02 определяется актуальностью политики и сохранённого подтверждения, а не произвольным повтором всего онбординга.

**Приёмка:** откат возвращает именно заявленный snapshot, текущая конфигурация не теряется; сброс действительно очищает локальные данные и не позволяет позднему ответу/индексации вернуть их; повтор восстановления не выполняет инструменты.

- [x] F09-V01. S11 строить из карточки ассистента, карточек инструкций/памяти/документов и строки модели; версии доступны из карточки инструкций, но сохраняют весь ассистент по ADR.

- [x] F09-V02. S14: согласовать максимум 30 графем для имени; отсутствие персонажа в web-экспорте вызвано dc-import и не отменяет preview. S15: отдельные retention toggles и фиксированный сброс; D05 сохраняет усиленное подтверждение.
