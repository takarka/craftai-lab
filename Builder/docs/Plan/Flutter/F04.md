# F04. Подключить аккаунт CraftAI

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B01: готовый auth/reset API. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F02/F03, auth-контракт backend.

- [x] F04-01. Реализовать вход, регистрацию с условиями/политикой, валидацию и показ/скрытие пароля.
- [x] F04-02. Реализовать единое сообщение ошибки неверного e-mail/пароля, duplicate registration и отказ сети.
- [x] F04-03. Сделать восстановление пароля: запрос письма, подтверждение отправки, app/universal link, новый пароль.
- [x] F04-04. На клиенте проверять host/scheme reset-ссылки, показывать ошибки истёкшего/повторного токена из B01 и не логировать URL. Проверка срока и одноразовости сервером выполняется исключительно в B01.
- [x] F04-05. Реализовать secure token storage, single-flight refresh, отзыв, logout и истёкшую сессию.
- [x] F04-06. После входа открывать workspace того же владельца и определять локальное завершение онбординга.
- [x] F04-07. При offline/refresh error не зацикливать переходы, не стирать ассистента, не показывать данные другому владельцу.
- [x] F04-08. Не добавлять Google/Apple login и обязательное подтверждение e-mail, если этого нет в согласованном контракте.

**Приёмка:** реальные сценарии CraftAI работают на обеих платформах; восстановление по валидной/просроченной ссылке проверено; секреты не попадают в БД общего назначения и логи.

## Выполненная клиентская часть S00

- [x] F04-UI-01. Формы входа и регистрации на основе визуального S00: имя, почта, пароль, повтор, показать/скрыть, RU/KK, общий аккаунт CraftAI.
- [x] F04-UI-02. Обязательные поля, базовый e-mail формат, совпадение паролей и типизированные ошибки неверных credentials/занятого аккаунта/сети/слабого пароля/rate limit. Сложность пароля остаётся политикой B01.
- [x] F04-UI-03. Клиент запроса восстановления: поле почты → ожидание → нейтральное «Проверьте почту» только после успешного результата адаптера; без раскрытия наличия аккаунта.
- [x] F04-UI-04. Root-страницы документов, явное согласие на их язык/revisions, запрет регистрации при отсутствии/пустом тексте документов.
- [x] F04-UI-05. Одна отправка одновременно, очистка паролей при фоне/переходе/завершении попытки, безопасная обработка неизвестной ошибки и позднего результата после dispose.

**Граница готовности:** F04 клиентский контур полностью реализован:
- Аппаратное защищённое хранилище токенов `SecureTokenStorage` (Keystore/Keychain).
- Сессионный репозиторий `PersistentSessionRepository` с mutex single-flight refresh, устойчивостью к offline-ошибкам (не стирает базу ассистента) и проверкой завершения онбординга по БД.
- Валидатор ссылок сброса пароля `ResetPasswordLinkValidator` (проверка схемы HTTPS, доверенного хоста, формата токена, без логирования URL).
- Маршрут `/reset-password` в `GoRouter` и форма сброса пароля в `AuthPage`.
- Поддержка языков RU и KK для всех новых сообщений сброса пароля.
- 13 модульных и интеграционных тестов F04 в `test/session_and_auth_test.dart` (все 96 тестов проекта зелёные).

**Остаётся для живой приёмки:** серверный контур B00/B01 на бэкенде (реальный HTTP transport и live reset email delivery). Полный статус — [журнал реализации](implementation-status.md).
