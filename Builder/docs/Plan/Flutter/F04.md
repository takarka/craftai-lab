# F04. Подключить аккаунт CraftAI

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B01: готовый auth/reset API. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F02/F03, auth-контракт backend.

- [ ] F04-01. Реализовать вход, регистрацию с условиями/политикой, валидацию и показ/скрытие пароля.
- [ ] F04-02. Реализовать единое сообщение ошибки неверного e-mail/пароля, duplicate registration и отказ сети.
- [ ] F04-03. Сделать восстановление пароля: запрос письма, подтверждение отправки, app/universal link, новый пароль.
- [ ] F04-04. На клиенте проверять host/scheme reset-ссылки, показывать ошибки истёкшего/повторного токена из B01 и не логировать URL. Проверка срока и одноразовости сервером выполняется исключительно в B01.
- [ ] F04-05. Реализовать secure token storage, single-flight refresh, отзыв, logout и истёкшую сессию.
- [ ] F04-06. После входа открывать workspace того же владельца и определять локальное завершение онбординга.
- [ ] F04-07. При offline/refresh error не зацикливать переходы, не стирать ассистента, не показывать данные другому владельцу.
- [ ] F04-08. Не добавлять Google/Apple login и обязательное подтверждение e-mail, если этого нет в согласованном контракте.

**Приёмка:** реальные сценарии CraftAI работают на обеих платформах; восстановление по валидной/просроченной ссылке проверено; секреты не попадают в БД общего назначения и логи.

## Выполненная клиентская часть S00

- [x] F04-UI-01. Формы входа и регистрации на основе визуального S00: имя, почта, пароль, повтор, показать/скрыть, RU/KK, общий аккаунт CraftAI.
- [x] F04-UI-02. Обязательные поля, базовый e-mail формат, совпадение паролей и типизированные ошибки неверных credentials/занятого аккаунта/сети/слабого пароля/rate limit. Сложность пароля остаётся политикой B01.
- [x] F04-UI-03. Клиент запроса восстановления: поле почты → ожидание → нейтральное «Проверьте почту» только после успешного результата адаптера; без раскрытия наличия аккаунта.
- [x] F04-UI-04. Root-страницы документов, явное согласие на их язык/revisions, запрет регистрации при отсутствии/пустом тексте документов.
- [x] F04-UI-05. Одна отправка одновременно, очистка паролей при фоне/переходе/завершении попытки, безопасная обработка неизвестной ошибки и позднего результата после dispose.

**Граница готовности:** эти UI-подзадачи не закрывают F04-01–F04-07 целиком. `AuthGateway` — клиентский порт, а не объявление готового HTTP API. Production использует отключённый адаптер, без fake сессии и писем. Тестовый адаптер находится только в `test/`.

**Остаётся:** B00/B01 и утверждённые юридические документы/парольная политика; F03 secure storage/owner workspace; реальный adapter, refresh/revoke/logout, проверенные reset app/universal links и форма нового пароля. Нет живой интеграции и native-приёмки. Полный статус — [журнал реализации](implementation-status.md).
