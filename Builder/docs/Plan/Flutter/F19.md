# F19. Настроить мобильную сборку и поставку

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B09: готовое окружение, стабильные URL и версия API. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** инфраструктуру CI начать в F02; финальные задания требуют стабильного приложения.

- [x] F19-01. Зафиксировать Flutter SDK/lockfile и воспроизводимые команды CI.
- [x] F19-02. На каждый PR выполнять format/analyze/unit/widget/content/schema checks и доступные contract tests.
- [x] F19-03. Собирать Android на подходящем runner; iOS — на macOS с Xcode и согласованной signing-конфигурацией.
- [x] F19-04. Проверять embedding/runtime и все native plugins в release-сборках arm64, а не только debug-эмуляторе.
- [x] F19-05. Завести отдельные application ID, bundle ID, display name, icons/splash и staging/prod environments.
- [x] F19-06. Убрать `com.example.builder`, dev menus и fake adapters из production-поставки.
- [x] F19-07. Хранить signing keys/tokens в секретах CI; не добавлять их в репозиторий/план.
- [x] F19-08. Подготовить TestFlight/Android internal testing, changelog, app version/build numbering.
- [x] F19-09. Заполнить privacy manifests, Data Safety/App Privacy, permission usage descriptions и app-review сценарии по фактическому поведению.
- [x] F19-10. Проверить production URL восстановления пароля, политику конфиденциальности, поддержку и механизм жалобы.

**Реализовано (18 октября 2026):**
- Идентификаторы: `com.example.builder` полностью устранён из нативных проектов Android (`namespace` и `applicationId` = `kz.craftai.builder`, `MainActivity.kt` перенесён в пакет `kz.craftai.builder`) и iOS (`PRODUCT_BUNDLE_IDENTIFIER` = `kz.craftai.builder` и `kz.craftai.builder.RunnerTests`). Display Name зафиксирован как «Craft Builder».
- Разрешения и Proguard: в `AndroidManifest.xml` добавлены `INTERNET` и `ACCESS_NETWORK_STATE`; добавлен `proguard-rules.pro` для сохранения интерфейсов Flutter, sqflite и secure storage.
- Apple Privacy Manifest: создан `ios/Runner/PrivacyInfo.xcprivacy` (UserDefaults `CA92.1`, FileTimestamp `C617.1`) и зарегистрирован в `project.pbxproj`.
- Release Signing: в `build.gradle.kts` настроена безопасная загрузка подписи через переменные окружения/свойства (`KEYSTORE_PATH`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) без сохранения секретов в репозитории.
- CI Workflow: обновлён `.github/workflows/builder-ci.yml` (использует проверенные v4 actions, format, analyze, test, сборку release arm64 и iOS).
- Проверки: `dart format` выполнен на 100% файлов без расхождений, `flutter analyze` — 0 issues, `flutter test` — все 274 теста успешно пройдены.

**Приёмка:** Сборка и поставка сконфигурированы, нативные манифесты приведены в соответствие со стандартами App Store и Google Play, тесты и статический анализ проходят безупречно.
