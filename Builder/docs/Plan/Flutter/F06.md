# F06. Подключить каталог моделей и сетевую основу

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B02: каталог; B03: транспорт. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F02/F04/F05, generation/model contracts.

- [x] F06-01. Реализовать клиент CraftAI с timeout/cancel, error mapping, request correlation и redaction.
- [x] F06-02. Загрузить три категории и возможности, отделив category ID от конкретного provider model ID.
- [x] F06-03. Выбирать рабочую категорию по умолчанию; хранить выбор в локальной конфигурации и версии.
- [x] F06-04. Собрать S33 с назначением, сравнительными шкалами, доступностью и чипом данных.
- [x] F06-05. Помечать относительные шкалы как справочные, не как гарантии точности или времени ответа.
- [x] F06-06. Кэшировать каталог; offline разрешать локальное изменение выбора с понятным ограничением разговора.
- [x] F06-07. При недоступной категории предлагать альтернативу; не менять модель незаметно и не делать автоматический повтор, увеличивающий стоимость.
- [x] F06-08. Зафиксировать capabilities и фактическую модель в trace каждого запроса, чтобы последующая смена каталога не переписала историю.

**Приёмка:** backend может заменить конкретную модель без Flutter-релиза; старый ответ продолжает показывать реально использованную модель; в APK/IPA и клиентском трафике нет прямого доступа к OpenRouter.

- [x] F06-V01. S33: поддержать трёхсегментные шкалы качества/скорости/цены; не навязывать пятисегментный компонент UI Kit. Значения относительные, без тарифной квоты.
