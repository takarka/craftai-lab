# F20. Провести сквозную приёмку и первый пилот

[Все этапы Flutter](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только Flutter, локальные данные, native-адаптеры, клиентские тесты и мобильная поставка.

**Внешний вход backend:** B09: опубликованная серверная версия, прошедшая собственную приёмку. Получение готового API/отчёта не является серверной работой этого этапа.

**Граница:** здесь не создавать серверные endpoints, БД, gateway, provider config или backend deployment. Если API не готов, использовать явно обозначенные contract fixtures для разработки; живую приёмку оставить заблокированной. Упоминания разделов/ADR/T-сценариев относятся к общему плану.

**Зависимость:** F00–F19, реальное окружение CraftAI.

- [ ] F20-01. Пройти полную матрицу FR/NFR и экранов, сохранив ссылки на результаты проверок.
- [ ] F20-02. Новый аккаунт на чистой установке: onboarding → ответ → trace → пять уровней → инструменты/MCP → восстановление → общий сброс.
- [ ] F20-03. Пройти тот же сценарий с отказом D02/OS permission, нестабильной сетью, app kill и сменой языка.
- [ ] F20-04. Проверить сохранность данных при обновлении с предыдущей пилотной сборки.
- [ ] F20-05. Провести первый пилот на устройстве автора; не заявлять заранее готовность масштабного школьного внедрения.
- [ ] F20-06. После авторского пилота организовать проверку понятности с учителями, в том числе с казахским основным языком, если подтверждён формат следующего пилота.
- [ ] F20-07. Проверить понимание: где обработаны данные, откуда ответ по документу, кто выполняет действие, что сбрасывается.
- [ ] F20-08. Разделить баги, проблемы контента, ограничения модели и новые пожелания; последние не включать незаметно в MVP.
- [ ] F20-09. Утвердить release checklist, поддержку, known limitations и порядок отката версии приложения без потери локальной БД.

**Работа начата (18 октября 2026):** создан [журнал F20-приёмки](F20-acceptance-log.md) с привязкой T01–T37 к кандидатам в тестах и фактическими блокерами. Наличие теста помечено как кандидат, не как пройденный сценарий. Живой сценарий требует B09; native сценарии — подписанных сборок и устройств; F16 analyzer/tests baseline сейчас не зелёный. Сквозные критерии остаются открыты.

**Выход:** критерии раздела 21 выполнены, обязательные неизвестные закрыты; результатом является работающий мобильный продукт, а не завершённый набор экранов.
