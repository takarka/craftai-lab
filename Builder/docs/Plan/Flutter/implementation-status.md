## F01: доступное окружение

Проверено: Flutter **3.47.7**, Dart **3.13.5**, Linux executor. Flutter расположен в `/workspace/toolchains/flutter/bin`; путь не является частью переносимой конфигурации проекта. В этой сессии команды выполняются абсолютным путём.

`flutter doctor -v` не обнаруживает Android SDK. iOS требует macOS/Xcode, физические Android/iPhone не подключены. Chromium доступен как `/usr/bin/chromium` для web preview. Native-календарь, Keychain/Keystore, backup, parser/embedding/runtime и RAG на телефоне **не проверены**. F01 остаётся открытым; storage/native технологии не выбраны.

## F02: выполненная независимая часть

- `main.dart` → bootstrap → `BuilderApp`: отдельная точка приложения. Production entry не импортирует gallery и не подключает demo controllers.
- `main_gallery.dart`: отдельный DEV-вход UI Kit; release-запуск отклоняется. Существующие интерактивные примеры сохранены.
- `APP_ENV=dev|staging|prod`, по умолчанию prod; `CRAFTAI_API_BASE_URL` необязателен до подключения API. URL не выдумывается. Разрешён HTTPS; HTTP — только loopback в dev. Credentials/query/fragment в base URL запрещены; ошибка не раскрывает исходное значение.
- Riverpod 3.4.3 (MIT), go_router 18.1.0 (BSD-3-Clause), Flutter localizations и intl. Lockfile фиксирует разрешённые версии. Проверены metadata пакетов; новые router/state пакеты не требуют native permissions/plugins. Фактические требования зависимостей отражены в pubspec: Dart ≥3.12, Flutter ≥3.44. Проверенная версия — 3.47.7.
- Session repository port и закрытое по умолчанию состояние SignedOut. Нет fake-login, fabricated user, credentials, HTTP-запросов и записи пользовательских данных. Реальный secure session adapter — F04 после F03/B01.
- Три отдельных navigator stack: `/assistant`, `/course`, `/profile`. Пока сессия загружается/ошибочна — `/startup`; без сессии — `/sign-in`; до завершения онбординга — `/onboarding`. При смене owner пересоздаются route stacks. Реальные owner namespaces и очистка async caches — последующая работа F03.
- Вкладки пока содержат явные сообщения о недоступных функциях; они не являются готовыми S10/S20/S50. Форм входа/регистрации и кнопки обхода авторизации нет. Они реализуются в F04, онбординг — F05.
- RU/KK через ARB/gen_l10n, выбор языка интерфейса; локализация новых страниц. Выбор пока живёт в памяти; сохранение настроек — F03/F16. Полная локализация UI Kit/контента — F17.
- Единая модель платформенных возможностей: web/desktop не поддерживают native actions; iOS/Android требуют native-проверки. Это не выданное OS permission и не обещание рабочего адаптера.

Независимый каркас F02 начат с явными ограничениями F00/F01. Этап F02 целиком не завершён: нужны реальные repositories/use cases, расширение типизированных ошибок, root overlays/deep links из будущих функций, интеграция API и native-проверки. Новые endpoint, серверные данные и backend pipeline не создавались.

## Проверка и продолжение

Проверки кода: `flutter analyze`, `flutter test`, `flutter build web --release`. Widget fixtures с подтверждённой сессией существуют только в тестах. Проверяются guards, блокировка защищённых маршрутов, переходы onboarding/ready/logout, смена владельца, ошибки сессии, смена RU/KK, URL-валидация и отсутствие галереи в production entry. Все **39 тестов прошли**: 22 существующих UI Kit + 17 новых. `flutter analyze` — без замечаний. Release web-сборка успешно создана; в Chromium на 390×844 проверены запуск и переключение RU → KK через меню языка, JavaScript page errors отсутствуют. Добавлен шрифт `cupertino_icons` для Cupertino-представлений router: сборка не должна терять соответствующие glyphs. Скриншоты проверки сохранены вне репозитория в артефактах сессии. Native-приёмку это не заменяет.

Следующая работа: закрывать native probes F01 в подходящем окружении и продуктовые ADR из таблицы; затем выбирать storage F03 и подключать настоящий session adapter F04 по готовым B00/B01. До этого нельзя объявлять готовыми вход, облачные ответы, локальные данные или весь F02.
