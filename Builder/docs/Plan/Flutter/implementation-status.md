## F02: выполненная независимая часть

- `main.dart` → bootstrap → `BuilderApp`: отдельная точка приложения. Production entry не импортирует gallery и не подключает demo controllers.
- `main_gallery.dart`: отдельный DEV-вход UI Kit; release-запуск отклоняется. Существующие интерактивные примеры сохранены.
- `APP_ENV=dev|staging|prod`, по умолчанию prod; `CRAFTAI_API_BASE_URL` необязателен до подключения API. URL не выдумывается. Разрешён HTTPS; HTTP — только loopback в dev. Credentials/query/fragment в base URL запрещены; ошибка не раскрывает исходное значение.
- Riverpod 3.4.3 (MIT), go_router 18.1.0 (BSD-3-Clause), Flutter localizations и intl. Lockfile фиксирует разрешённые версии. Проверены metadata пакетов; новые router/state пакеты не требуют native permissions/plugins. Фактические требования зависимостей отражены в pubspec: Dart ≥3.12, Flutter ≥3.44. Проверенная версия — 3.47.7.
- Session repository port и закрытое по умолчанию состояние SignedOut. Нет fake-login, fabricated user, credentials, HTTP-запросов и записи пользовательских данных. Реальный secure session adapter — F04 после F03/B01.
- Три отдельных navigator stack: `/assistant`, `/course`, `/profile`. Пока сессия загружается/ошибочна — `/startup`; без сессии — `/sign-in`; до завершения онбординга — `/onboarding`. При смене owner пересоздаются route stacks. Реальные owner namespaces и очистка async caches — последующая работа F03.
- Вкладки пока содержат явные сообщения о недоступных функциях; они не являются готовыми S10/S20/S50. Добавлены формы входа/регистрации/запроса восстановления; production отправка отключена до реальной интеграции F04. Кнопки обхода авторизации нет, онбординг — F05.
- RU/KK через ARB/gen_l10n, выбор языка интерфейса; локализация новых страниц. Выбор пока живёт в памяти; сохранение настроек — F03/F16. Полная локализация UI Kit/контента — F17.
- Единая модель платформенных возможностей: web/desktop не поддерживают native actions; iOS/Android требуют native-проверки. Это не выданное OS permission и не обещание рабочего адаптера.

Независимый каркас F02 начат с явными ограничениями F00/F01. Этап F02 целиком не завершён: нужны реальные repositories/use cases, интеграция API и native-проверки. Типизированные ошибки и root overlays юридических документов теперь добавлены; reset deep links остаются отдельной задачей F04. Новые endpoint, серверные данные и backend pipeline не создавались.

## Продолжение: клиентский S00 и auth routes

Baseline продолжения: `38c66b9`. Форма повторяет визуальные токены S00, использует существующие персонаж/кнопки/карточки и дополняет отсутствующие в прототипе registration/recovery состояния из дизайн-ТЗ. Все новые строки доступны RU/KK; семантическая подпись персонажа и ожидания локализована. В BuilderButton добавлен необязательный loadingLabel, существующие галерейные вызовы совместимы.

Клиентские слои: безопасные AppFailureCode без response payload, AuthGateway port, autoDispose AuthController с single-flight и защитой от позднего обновления после dispose, формы/локальные validators. Email/name очищаются от крайних пробелов; пароль передаётся без trim. Никакие form credentials не помещаются в provider state, router URL, файлы или логи. Вызов адаптера может удерживать immutable-строки в памяти до завершения запроса; физическое обнуление heap не заявляется.

Public auth routes доступны без сессии; существующие защищённые вкладки и onboarding guard сохранены. Успешный результат команды не создаёт UI-сессию: готовый session adapter должен опубликовать её только после secure persistence. Root legal page сохраняет navigator stack вкладки. При смене owner старые stacks по-прежнему уничтожаются.

Юридические тексты не придуманы. Пока нет approved документов для языка с непустыми body/revision, checkbox и регистрация отключены. Согласие хранится только в локальном состоянии формы и привязано к языку, terms revision и privacy revision. Смена языка требует нового согласия. Смена почты при recovery не отправляет автоматически новые запросы; неизвестный аккаунт не раскрывается текстом результата.

**Открытые зависимости:** настоящие auth endpoints/DTO/error mapping/password policy/approved documents/reset-link hosts из B00/B01, secure storage и workspace F03, реальный F04 adapter и refresh, проверка email-link и новый пароль, native iOS/Android. Веб-формы не считаются завершённым входом или всем F04. Backend-код не изменялся.

### Проверка продолжения S00

`flutter analyze` — без замечаний. Все **55 тестов прошли**: 22 UI Kit, 17 каркаса и 16 auth-сценариев. Включены попытки повторной отправки, ошибочные credentials, нейтральное восстановление, versioned consent, пустые документы, смена языка, lifecycle/переходы, поздний ответ после dispose и отмена системного autofill-save на выходе из неподтверждённой формы. Проверка keyboard/insets и текста 130% выполнялась на размере 320×640 в RU/KK.

AutofillGroup завершает контекст с `shouldSave=false`, чтобы навигация до настоящего входа не предлагала сохранить неподтверждённые credentials. Подтверждение сохранения после реальной авторизации — будущая интеграция F04; тест проверяет клиентский platform-channel вызов, не поведение всех native password managers.

Release web-сборка успешно создана. В Chromium 390×844 пройдены вход → регистрация → root-документ → возврат → восстановление → смена RU/KK; проверено отключение submit без адаптера. JavaScript page errors отсутствуют. Скриншоты визуальной проверки находятся вне git в `/workspace/artifacts/builder-auth-forms/`. Это подтверждение клиента, не живой auth и не native-приёмка.
