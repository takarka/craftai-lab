## F03: постоянное защищённое хранилище и изоляция владельцев

Реализована локальная модель данных и защищённое хранилище без передачи данных на сервер:

1. **Реляционная схема V1 (`StorageSchemaV1`):**
   - 18 нормализованных таблиц со строгими типами и внешними ключами (`PRAGMA foreign_keys = ON`).
   - Изоляция всех записей по `owner_id`.
   - Индексы для оптимизации выборок по владельцу, сессиям и временным меткам.

2. **Защита ключей и аутентифицированное шифрование:**
   - `SecureKeyStorage`: аппаратный Keystore/Keychain (`flutter_secure_storage`) для хранения 256-битного мастер-ключа.
   - `StorageCipher`: симметричное шифрование с верификацией целостности (HMAC-SHA256, 16-байтный IV, 32-байтный auth tag) для выявления любых модификаций или повреждений данных.

3. **Атомарные транзакции и журнал файлов (`FileStagingJournal`):**
   - Двухфазный коммит для согласования файловых операций с SQLite транзакциями.
   - Очистка брошенных staging-файлов при запуске приложения (`recoverInterruptedStaging`).

4. **Изоляция пространств и `workspaceEpoch` (`WorkspaceStorageService`):**
   - Управление активным владельцем, очистка кэшей и токенов в памяти при смене пользователя или выходе (`closeActiveWorkspace`).
   - Инкремент поколения (`bumpWorkspaceEpoch`) для защиты от устаревших асинхронных операций.
   - Полное локальное удаление данных владельца (`purgeOwnerData`) по ADR-04.

5. **Репозиторий начального пространства (`PersistentInitialWorkspaceRepository`):**
   - Атомарная транзакционная запись конфигурации онбординга.
   - Проверка `WorkspaceWritePermit.isCurrent` до и внутри транзакции.
   - Идемпотентность per owner: повторный вызов не дублирует и не перезаписывает активное пространство.

6. **Миграции и защита от скрытого сброса:**
   - Резервная копия `.bak` перед миграциями.
   - Запрет неявного `deleteDatabase()`: ошибка базы выбрасывает `StorageCorruptionException` с сохранением файлов для восстановления.

## F04: подключение аккаунта CraftAI, защищённая сессия и сброс пароля

Реализован полный клиентский контур авторизации и защищённого управления токенами:

1. **Модель токенов и аппаратное хранилище:**
   - `AuthTokens` с сериализацией/десериализацией JSON и проверкой срока действия `isExpired`.
   - `SecureTokenStorage` с реализацией для платформ `PlatformSecureTokenStorage` (Keystore на Android с `resetOnError: true`, Keychain на iOS) и `InMemorySecureTokenStorage` для тестов.

2. **Постоянный сессионный репозиторий (`PersistentSessionRepository`):**
   - Восстановление сохранённой сессии при старте приложения с автоматическим открытием изолированного `owner` пространства в SQLite.
   - Проверка локального завершения онбординга через таблицу `assistant_config`.
   - Mutex `single-flight` для предотвращения одновременных дублирующих запросов обновления токенов (`refreshTokens`).
   - Устойчивость к offline-ошибкам: сбои сети и временные таймауты обновления токенов не стирают локальные данные ассистента и не приводят к циклическому редиректу (F04-07).
   - Принудительный `signOut`: закрытие активного workspace, инкремент эпохи, сброс кэшей в памяти и удаление токенов из Keystore/Keychain.

3. **Сброс пароля и верификация ссылок (`ResetPasswordLinkValidator`):**
   - Валидация универсальных/app-ссылок сброса: проверка схемы (строго HTTPS), белого списка доверенных доменов (`craftai.kz`, `auth.craftai.kz` и хосты из `CRAFTAI_API_BASE_URL`), длины и символов токена.
   - Защита от утечек: нулевое логирование полного URL сброса в открытом виде.
   - Маршрут `/reset-password` в `GoRouter` с поддержкой извлечения токена из query-параметров (`token` / `t`).
   - Форма сброса пароля в `AuthPage`: валидация совпадения паролей, очистка секретов из памяти, вывод информативного сообщения при недействительной/просроченной ссылке.

4. **Локализация:**
   - Полная поддержка RU и KK для всех новых UI-состояний сброса пароля (`authResetPasswordTitle`, `authNewPassword`, `authConfirmNewPassword`, `authSavePassword`, `authResetSuccess`, `authInvalidResetLink`).

## F05: оболочка, онбординг и первое согласие D02

Реализован полный клиентский контур онбординга с постоянным хранилищем и модальным окном согласия на трансграничную передачу данных:

1. **Схема БД и персистентность политики (D02):**
   - Добавлена таблица `policy_acknowledgments` (`owner_id`, `policy_id`, `policy_version`, `acknowledged_at_utc`, PRIMARY KEY `(owner_id, policy_id)`).
   - Очистка таблицы при физическом удалении данных владельца (`purgeOwnerData`).
   - `PersistentPolicyRepository` с методами `isPolicyAcknowledged`, `getAcknowledgment`, `acknowledgePolicy` и in-memory реализацией `InMemoryPolicyRepository`.
   - Репозиторные провайдеры в `policy_providers.dart`.

2. **Модальное окно первого согласия (D02 Sheet):**
   - Компонент `D02ConsentSheet` и хелпер `showD02ConsentSheet` с `useRootNavigator: true`.
   - Полное визуальное соответствие токенам Builder: иконка глобуса, чипы цепочки данных (`Телефон` → `CraftAI` → `Модель`), блок предупреждения о защите данных учеников, кнопки «Понятно» и «Не сейчас».
   - Двуязычная локализация RU / KK (`app_ru.arb`, `app_kk.arb`).

3. **Связывание с онбордингом и отложенный режим:**
   - Интеграция `PersistentInitialWorkspaceRepository` в `OnboardingController` для атомарного создания workspace в SQLite.
