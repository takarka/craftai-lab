# B06. Учёт использования аккаунта

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00/B01/B03.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B06-01. Определить единицы input/output/total, временную зону/период и timestamp актуальности; согласовать scope общего аккаунта CraftAI.
- [ ] B06-02. Собирать счётчики из реальных usage событий провайдера без хранения текста запросов/ответов.
- [ ] B06-03. Дедуплицировать request ID и поздние usage события; определить cancelled/partial/unknown usage и eventual consistency.
- [ ] B06-04. Вернуть account usage API с ясным unavailable состоянием; не превращать отсутствие данных в ноль.
- [ ] B06-05. Не вводить 500k лимит, процент остатка, дату подписки или денежный баланс без отдельного решения продукта.
- [ ] B06-06. Проверить изоляцию аккаунтов и объём допустимых operational metadata.

## Результат

Согласованные реальные метрики аккаунта, без фиктивных квот.

## Проверки и критерий выхода

BT06: повторное событие, частичная генерация, граница периода, задержка, unknown usage и запрет чтения чужих счётчиков.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
