# B00. Контракты и аудит существующего CraftAI

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** нет; начинается параллельно F00.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B00-01. Инвентаризировать существующий auth, аккаунты, стек, gateway, deployment и готовые API CraftAI; переиспользовать общий аккаунт без создания отдельной базы идентичностей Builder.
- [ ] B00-02. Опубликовать версионируемые OpenAPI/JSON schemas: auth/profile/catalog/generation/tool continuation/search/MCP/usage/delete/report; перечислить реально существующие и новые операции.
- [ ] B00-03. Определить domain error codes, requestId, version, correlation, HTTP-коды, таймауты, совместимость и правила изменения схем.
- [ ] B00-04. Описать события потока, fragmented UTF-8/JSON, sequence/eventId, finish/cancel/error, partial usage, tool-call ID и необязательный replay; не обещать replay без реализации.
- [ ] B00-05. Разделить локальные assistant state/документы/индекс/память/курс и серверные account/session/usage. Не создавать sync локального ассистента.
- [ ] B00-06. Зафиксировать разрешённые payloads и границы доверия: данные модели и tool arguments недоверенные; только allowlist инструментов.
- [ ] B00-07. Подготовить обезличенные fixtures успешных/ошибочных ответов и список переменных окружения без секретов.
- [ ] B00-08. Оформить точные схемы search_lessons/get_lesson как предложение S44 и утвердить либо документировать реальные имена.

## Результат

Версионируемый контракт, инвентаризация существующего API, таблица владения данными и fixtures.

## Проверки и критерий выхода

BT00: автоматическая валидация примеров по схемам, совместимость версий и отсутствие секретов; ни один неподтверждённый endpoint не отмечен готовым.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
