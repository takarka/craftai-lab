# B02. Каталог моделей и серверная конфигурация

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00; B01 для защищённого доступа.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B02-01. Сопоставить три категории модели с реально доступными OpenRouter model IDs; хранить ключи и mapping только на сервере.
- [ ] B02-02. Возвращать revision, capability flags, доступность, RU/KK поддержку, ограничения и согласованные относительные шкалы S33.
- [ ] B02-03. Проверить текст/function calling на обезличенных RU/KK задачах; не обещать универсальный рейтинг качества.
- [ ] B02-04. Разрешить замену моделей конфигурацией с аудитом и возможностью отката, не требуя мобильного релиза.
- [ ] B02-05. Реализовать существующий безопасный административный механизм FR-CMS-03; отдельную полноценную CMS не включать в MVP.
- [ ] B02-06. Разделить технические transport/document limits и тарифы; не выдавать 500k/38% из S50 за продуктовую квоту.
- [ ] B02-07. Определить cache/revision/недоступность категории и ошибки при устаревшей capabilities; не скрывать смену модели во время запроса.

## Результат

Реальный model catalog и защищённый механизм изменения mapping.

## Проверки и критерий выхода

BT02: смена/revert mapping без клиента, отсутствующая модель, неверные capabilities, RU/KK smoke tests, отсутствие provider key в ответах.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
