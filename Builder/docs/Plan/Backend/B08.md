# B08. Серверная безопасность и наблюдаемость

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00; проверять с первого backend этапа, финальная проверка B01–B07.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B08-01. Составить data map gateway/proxy/APM/провайдера, согласовать сроки обработки/retention и truthful пользовательские раскрытия.
- [ ] B08-02. Убрать тела диалогов, snippets, tool payloads, пароли и reset URLs из access/error/debug logs, tracing, APM и crash reports по умолчанию.
- [ ] B08-03. Хранить secrets через принятую инфраструктуру, ограничить доступ, определить rotation и окружения; проверить репозиторий/контейнеры на утечки.
- [ ] B08-04. Проверить authz каждого account endpoint, allowlist egress, SSRF, schema/size limits, dependency vulnerabilities и защиту от abuse.
- [ ] B08-05. Метрики строить на status/latency/correlation без содержания; описать инциденты, алерты и трассировку без восстановления частного текста.
- [ ] B08-06. Проверить реальные политики OpenRouter/search/MCP и регион обработки, не выдавать серверное no-retention за гарантию стороннего провайдера.
- [ ] B08-07. Подготовить отчёт и обезличенные доказательства для F18; локальная БД/OS permissions и client crash reports здесь не проверяются.

## Результат

Серверный security/privacy report и operational runbook.

## Проверки и критерий выхода

BT08: canary secrets/private strings не появляются в logs/APM, cross-account access запрещён, egress/abuse проверки проходят, rotation и revoke воспроизводимы.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
