# B07. Профиль, жалобы и жизненный цикл аккаунта

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00/B01; B06 для account metrics.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B07-01. Описать server-owned поля профиля и валидируемый PATCH; локальный прогресс, предмет/настройки ассистента не синхронизировать скрытно.
- [ ] B07-02. Реализовать удаление аккаунта с re-auth/подтверждением, отзывом сессий, idempotency, статусом и согласованной retention policy.
- [ ] B07-03. Разделить серверное удаление аккаунта и локальный сброс D05; backend не удаляет события из календаря телефона.
- [ ] B07-04. Реализовать жалобу с минимальными metadata/report ID и только явно выбранным пользователем текстом; запретить автоприкладывание всего разговора.
- [ ] B07-05. Настроить маршрутизацию жалоб и поддержку по утверждённой политике; обещание одного рабочего дня из S56 использовать только при согласованном SLA.
- [ ] B07-06. Опубликовать privacy/support links и truthful data-location; не обещать отсутствие обработки у всех провайдеров.
- [ ] B07-07. Экспорт из S55 оставить отключённым после MVP; сейчас описать границу будущего account export отдельно от локального assistant archive.

## Результат

Profile/delete/report API, политики и воспроизводимые статусы.

## Проверки и критерий выхода

BT07: чужой account ID, повтор удаления, revoked sessions, partial failure, минимальность report payload и отсутствие доступа после удаления.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
