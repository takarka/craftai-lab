# B03. Генерация, streaming и продолжение инструментов

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00/B01/B02.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B03-01. Реализовать authenticated gateway CraftAI → OpenRouter; принять собранный клиентом контекст в утверждённой схеме без постоянного хранения диалога.
- [ ] B03-02. Проверять категории/capabilities, размеры, роли и allowlist tools; не принимать произвольный provider URL или секрет от клиента.
- [ ] B03-03. Стримить типизированные события с actual model ID, correlation/sequence, text deltas, tool-call start/delta/end, usage и terminal state.
- [ ] B03-04. Обрабатывать disconnect/stop/upstream timeout, ограничивать буферизацию reverse proxy; документировать реально возможную отмену и partial usage.
- [ ] B03-05. Проверять законченные tool arguments по JSON schema; не выполнять незавершённый JSON и не исполнять телефонные действия на сервере.
- [ ] B03-06. Принимать результат только для ожидаемого tool-call/request/session, ограничить цикл/время/размеры; определить dedup/retry без дублирующего внешнего действия.
- [ ] B03-07. Передавать реальное происхождение, временные метки и usage; недоступную метрику возвращать как unavailable, не синтезировать числа макета.
- [ ] B03-08. Возвращать структурированные upstream/network/auth/capability ошибки, сохранять совместимость схем и исключить утечки provider credentials.

## Результат

Рабочий поток текста и tool continuation с реальными метаданными.

## Проверки и критерий выхода

BT03: fragmented stream/UTF-8, duplicate sequence, cancel/disconnect, неполные arguments, неверный tool ID, timeout и bounded loop; позднее событие не возобновляет завершённый запрос.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
