# B01. Идентификация, сессии и восстановление

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B01-01. Подключить существующий общий аккаунт CraftAI; реализовать недостающие регистрацию/e-mail+пароль/login без Google/Apple и обязательной email-верификации в стартовом scope.
- [ ] B01-02. Валидировать входные поля; хранить пароль только через принятую безопасную password-hash систему существующего backend.
- [ ] B01-03. Определить access/refresh TTL, rotation, revocation и поведение конкурентного refresh; logout отзывает требуемую сессию.
- [ ] B01-04. Реализовать запрос восстановления без раскрытия существования e-mail и выпуск письма через настроенный серверный канал.
- [ ] B01-05. Проверять TTL, одноразовость, привязку и атомарное потребление reset token на сервере; повторный/истёкший токен возвращает стабильный код.
- [ ] B01-06. Настроить утверждённые HTTPS URL reset и документы association для app/universal links; не включать token в логи.
- [ ] B01-07. Добавить защиту от перебора/abuse и перечисления аккаунтов; технический rate limit не становится тарифной квотой.
- [ ] B01-08. Подготовить тестовые аккаунты и описать disabled/deleted/revoked session ответы.

## Результат

Рабочий auth API и sandbox восстановления с документированным жизненным циклом сессии.

## Проверки и критерий выхода

BT01: регистрация/ошибки/refresh race/logout/истёкший и повторный reset, enumeration и rate limit; отозванная сессия больше не допускается.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
