# B04. Серверный веб-поиск

[Все этапы backend](README.md) · [Общий план](../flutter-implementation-plan.md)

**Контур:** только сервер CraftAI, его контракты, данные, интеграции, тесты и deployment.

**Зависимости:** B00/B01/B03.

**Граница:** не изменять Flutter UI, native-плагины, локальную БД телефона, курс/прогресс или мобильный CI. Готовность клиента не блокирует серверные contract tests. Стек выбирать по аудиту B00 существующего CraftAI.

## Задачи

- [ ] B04-01. Подключить утверждённый search provider и хранить его credentials на сервере.
- [ ] B04-02. Валидировать поисковый запрос, объём и allowlist операции; исключить превращение endpoint в произвольный HTTP proxy/SSRF.
- [ ] B04-03. Принимать только согласованный минимальный payload, не требовать загрузки локального документа или всей истории.
- [ ] B04-04. Возвращать ссылки, заголовки, snippets, provider/source и фактические длительности с ограничением размера.
- [ ] B04-05. Добавить timeout/cancellation/rate limits и унифицированные ошибки; не подменять провал поиска выдуманными результатами.
- [ ] B04-06. Связать результат с request/tool-call и scope сессии; описать отсутствие доступа/отозванный grant.
- [ ] B04-07. Проверить, что metadata для trace не раскрывают секретные URL и provider key.

## Результат

Ограниченный search gateway и документированный минимальный payload.

## Проверки и критерий выхода

BT04: реальные/пустые результаты, timeout, invalid input, SSRF попытки, revoked session и корректное происхождение результатов.

Все обязательные задачи выполнены, контракт и примеры опубликованы, серверные отрицательные сценарии пройдены. Наличие макета или клиентской заглушки не подтверждает готовность backend.
