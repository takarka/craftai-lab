# ПР-01 — приёмка Skills на реальной модели

Владелец сообщил о самостоятельной ручной проверке 19.10.2026, затем уточнил: только Android и не полностью. Полный протокол ПР-01 не приложен; ниже сценарий для завершения проверки. Автоматические тесты с тестовым SSE не заменяют эту проверку.

## Подготовка

Нужны доступный CraftAI API, тестовый аккаунт, доступная модель и настроенный `CRAFTAI_API_BASE_URL`. Не записывать пароли и токены в отчёт. Использовать вымышленные учебные данные без имён учеников.

Открыть урок Skills после первых двух тем. Сохранить копию шаблона проверочной работы: класс 6, тема «Дроби». Записать версию ассистента и ревизию навыка до изменений.

## Сценарий

1. Оставить обязательный вход «Класс» пустым. Попытаться подготовить запуск. Ожидается запрос недостающего ввода; сообщения модели и нового trace нет.
2. Указать класс 6, тему «Дроби». Проверить карточку входов, явно запустить навык и принять D02, если согласие ещё не дано. Дождаться завершённого ответа. Проверить соответствие теме, классу, формату и критериям сохранённого навыка.
3. Открыть «Под капотом». Во вкладках «Схема», «Рентген» и «Аналогия» проверить название, ревизию навыка и фактически отправленные входы. Заявленные источники не должны выдаваться за прочитанные документы.
4. Изменить навык: добавить проверяемое требование «Ровно три задания и ответы отдельным блоком». Сохранить новую версию. Запустить тот же навык для темы «Энергия», класс 6. Проверить новый формат и отсутствие подмены темы предыдущим вводом. Практика урока должна засчитаться только после двух завершённых запусков с изменением навыка между ними.
5. Восстановить версию до изменения. Повторно открыть карточку: прежний сценарий восстановлен, новое требование отсутствует. Само восстановление не отправляет запрос и не включает инструменты, память или расписание.
6. Отдельно проверить отказ D02 (если доступен свежий тестовый профиль), остановку генерации и ошибку сети: ввод сохраняется, завершённый ответ не подделывается, незавершённый запуск не засчитывается как успешная практика. После восстановления сети повторить запуск вручную.

## Доказательства

Для каждого шага записать: дату, commit, среду/устройство, локаль, результат, request ID и фактическую модель (если сервер её сообщил). Сохранить обезличенные тексты двух ответов и снимки трёх вкладок trace. Проверку KK и Android/iOS отмечать отдельно, только после фактического выполнения.

Если ответ не соответствует критерию, сохранить фактический результат и дефект; ПР-01 не закрывать. Текущий статус и ссылки на доказательства вести в [progress.md](progress.md).
