# Craft Builder — журнал решений по оставшейся работе (ADR)

Дата: 19.10.2026. Решения владельца продукта, принятые при составлении [плана выполнения](03-execution-plan.md). Закрывает R-00-P в части перечисленных вопросов; статус задачи ведётся в [progress.md](progress.md).

| № | Решение | Причина | Последствия |
|---|---|---|---|
| D-01 | Backend Builder — `ai-sana/platform/back`, модуль Builder; новые endpoint'ы добавляются туда. | Модуль уже содержит шлюз, поиск, auth, каталог моделей. | R-00-B сверяет B00–B09 с этим репозиторием. |
| D-02 | Файлы TXT/DOCX/PDF разбираются и собираются отдельным Python-воркером. | Лучшее качество разбора PDF и проще работа с DOCX. | Новый сервис по образцу `platform/runner`, сам runner не используется. Контракт .NET ↔ воркер и лицензии библиотек (в т.ч. PyMuPDF/AGPL) — в EB-00. Спайк на 10–20 реальных RU/KK файлах до полной реализации. |
| D-03 | Собственный календарь Builder на сервере CraftAI полностью заменяет календарь телефона. | Нативный доступ к календарю сложен и рискован. | Новый этап EB-06; native-разрешения календаря не нужны; события хранятся на сервере: согласие, срок хранения, удаление с аккаунтом, privacy/store declarations. |
| D-04 | Автоматизация уровня 7 — серверное расписание. | Сервер видит календарь Builder и может запускать задачи без открытого приложения. | EB-03 и EB-04 применяются; напоминание о занятии — локальное уведомление OS, готовность результата — push. |
| D-05 | В первой версии только два шаблона расписаний: Daily Brief и генератор идей; свободное создание отложено. | Упрощает приёмку; серверный механизм остаётся общим. | Начальные лимиты зафиксированы в [плане выполнения](03-execution-plan.md#модель-серверных-расписаний-eb-00-eb-03-ef-07). |
| D-06 | Звонки/SMS из F01 исключены из выпуска. | Не основной учебный сценарий. | Убрать из интерфейса и текстов в EF-00. |
| D-07 | Уровни 8 и 9, MCP, голос и зрение вне выпуска. | Как в исходном плане. | — |
| D-08 | Знания и память остаются на телефоне; серверный запуск получает только явно выбранный пользователем фрагмент. | Сохранение прежней политики данных. | Фрагмент ограничен по размеру (начально 20 КБ). |
| D-09 | Push через FCM для Android и iOS. | Один провайдер и один серверный клиент. | Нужны проект Firebase и ключ APNs для iOS; ключи только на сервере. |
| D-10 | Повторения календаря — собственное разворачивание ограниченного набора правил (daily/weekly), без Ical.Net. | Самый быстрый путь, нет лицензионных вопросов. | Месячные и годовые правила не поддерживаются; обязательны тесты на DST. |
| D-11 | Окна догона запусков: Daily Brief 6 часов, идеи 24 часа. | Начальные значения. | Уточнить после измерений. |
| D-12 | Библиотеки Python-воркера (свободные лицензии): разбор PDF — `pdfplumber` (MIT, на `pdfminer.six`) с запасным `pypdf` (BSD-3); DOCX — `python-docx` (MIT); создание PDF — `reportlab` (BSD, открытая версия); шрифт — Noto Sans (SIL OFL, есть кириллица и казахские буквы). `PyMuPDF` исключён (AGPL). | Бесплатно, допустимо для закрытого сервиса. | Лицензии и версии сверить при фиксации зависимостей; качество на RU/KK PDF проверить спайком, когда появятся реальные файлы. |
