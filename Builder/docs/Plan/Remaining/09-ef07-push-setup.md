## Что подключено

На экране «AI-расписания» есть отдельная карточка уведомлений RU/KK: включить, обновить регистрацию, выключить. Разрешение OS запрашивается только после нажатия «Включить push». Согласие сохраняется отдельно для каждого владельца; другой аккаунт по умолчанию не подписан. Локальные календарные напоминания имеют собственный переключатель, хотя системное разрешение уведомлений общее для приложения.

Клиент отправляет `PUT /builder/devices/{installationId}` с платформой, FCM registration token, RU/KK и версией установленного приложения. UUID установки сохраняется в secure storage. Токен FCM и access token не записываются в новый локальный реестр и не логируются. Перерегистрация выполняется при смене токена, возвращении в приложение, смене языка и вручную. APNs token на iOS может появиться позже: в этом случае показано ожидание, повтор выполняется при следующем возвращении/обновлении.

При выходе и замене владельца отзыв выполняется до очистки/замены credentials. HTTP-авторизация отзыва привязана к прежнему владельцу; она не обновляется токеном другого аккаунта. Команды сериализованы, поздние ответы отбрасываются; возвращение приложения в процессе logout не подписывает прежнего владельца заново. Клиент также выключает auto-init и удаляет локальный FCM token. При сетевой ошибке отзыв не объявляется подтверждённым; сохранённый installationId используется для повторного отключения при доступной авторизации того же владельца. Новая установка выделяется после подтверждённой очистки. Уже отправленное OS уведомление может оставаться в системном центре уведомлений; отзыв не обещает его удалить.

При `run.ready` принимается только UUID `runId`. URL и произвольные действия из payload не исполняются. В открытом приложении показывается нейтральный баннер с кнопкой «Открыть»; в фоне/после закрытия используется обычное notification-сообщение FCM и обработчик нажатия. `getInitialMessage` обрабатывает холодный запуск. Фоновая генерация/чтение содержимого результата на телефоне не выполняется.

Нажатие ведёт на `/automation/runs/{runId}`. Результат запрашивается с авторизацией текущего аккаунта; payload не считается источником его содержимого. Чужой, удалённый или истёкший результат показывает недоступность. При смене аккаунта стек навигации пересоздаётся, баннеры очищаются. Нейтральный push не содержит содержимого уроков/событий.

## Конфигурация Android

1. Добавить Android-приложение `kz.craftai.builder` в нужный Firebase-проект.
2. Поместить его настоящий файл в `Builder/android/app/google-services.json`. Файл исключён из Git; заглушка не создаётся. Google Services plugin 4.5.0 применяется только при наличии файла, поэтому сборка checkout без Firebase сохраняется.
3. Собрать с включённой интеграцией:

```powershell
flutter build apk --debug --dart-define=FIREBASE_PUSH_ENABLED=true
```

Без флага push показывает недоступность и Firebase из Dart не инициализируется. При флаге без корректного native-файла ошибка инициализации обрабатывается, но регистрация не считается успешной. Native-файл нужен также для инициализации SDK при закрытом приложении; одних параметров Dart для этого пути недостаточно. Auto-init Messaging по умолчанию выключен в AndroidManifest.

## Конфигурация iOS

1. Добавить iOS-приложение с bundle ID `kz.craftai.builder` в тот же проект.
2. Поместить настоящий файл в `Builder/ios/Runner/GoogleService-Info.plist` (исключён из Git). Build phase копирует существующий файл в bundle через `copy_firebase_config.sh`; отсутствующий файл не ломает обычную сборку.
3. На Mac выполнить `flutter pub get`, затем `pod install` в `ios/`; собирать `Runner.xcworkspace`. Добавлен стандартный Podfile, подключены xcconfig CocoaPods. Зависимость Firebase Core 5 требует **iOS 15+**: deployment target и AppFrameworkInfo обновлены с 13 до 15.
4. В Apple Developer включить Push Notifications для App ID и обновить provisioning profiles. Debug использует `PushDebug.entitlements` (`development`), Release/Profile — `PushRelease.entitlements` (`production`). `UIBackgroundModes` содержит fetch/remote-notification; method swizzling не отключён.
5. Загрузить ключ APNs в Firebase (секрет `.p8` остаётся вне репозитория). Собрать с `--dart-define=FIREBASE_PUSH_ENABLED=true` и проверить на настоящем устройстве.

Сборка iOS и provisioning в этой Windows-сессии не выполнялись. Подключение CocoaPods/подписи требует проверки на Mac; успешная Android-сборка не подтверждает iOS.

## Backend

В `ai-sana` уже реализован FCM HTTP v1. Серверу нужны `Builder__Push__ProjectId` и `Builder__Push__ServiceAccountJson`, заданные через секреты deployment-среды. Сервисный аккаунт и APNs private key не передаются в приложение. Клиентский native-файл содержит конфигурацию Firebase-приложения, а не серверный service account.

FlutterFire Messaging 17 вводит API `register/onRegistered` с FID. Действующий backend отправляет `message.token` через FCM HTTP v1 и принимает прежний registration token, поэтому адаптер намеренно использует пока поддерживаемые `getToken/onTokenRefresh/deleteToken`; deprecation подавлена только на этих вызовах с пояснением. Переход на новый direct-send target требует совместного изменения серверного контракта, а не замены значения поля `pushToken` на FID.
