# CraftAI Lab

## Быстрый просмотр без сервера — деморежим

Нужны только Flutter **3.47.7** и Chrome. Команды подходят для PowerShell,
bash и zsh. Из корня репозитория:

```powershell
cd Builder
flutter pub get --enforce-lockfile
flutter run -t lib/main_demo.dart -d chrome --web-hostname 127.0.0.1 --web-port 8080
```

Откроется [http://127.0.0.1:8080](http://127.0.0.1:8080). Python, регистрация,
API-ключи и запущенный backend не требуются. Данные существуют в памяти вкладки;
обновление страницы восстанавливает исходные примеры. Деморежим запускается
отдельной точкой входа и недоступен в release.

Что посмотреть:

1. Два готовых агента: математика для 5 класса и русский язык для 7 класса.
2. Создание, переименование, копирование, сброс и удаление агентов; лимит — пять.
3. «Открыть» → «Открыть демодиалог»: отправьте любой запрос.
4. Отправьте **«Сохрани материал»**, подтвердите или отклоните запись, затем
   откройте **«Как выполнено»**. **«Найди материалы»** показывает записи агента.
5. В настройках посмотрите примеры материалов и памяти, добавьте свои,
   отключите разрешение сохранения и повторите запрос.
6. Добавьте в инструкцию слово **«кратко»**, снова откройте диалог и сравните ответ.

Постоянный баннер отмечает деморежим. Ответы формируются по шаблонам:
они демонстрируют интерфейс и действия, а не работу настоящей модели.
Фото/OCR, серверные SSE, вход и курс в эту демонстрацию не входят.
Установка Flutter и первая загрузка пакетов требуют интернета; само демо
не отправляет запросы к API или моделям.

## Обычный запуск с сервером

Основное приложение находится в [`Builder/`](Builder/), сервер — в
[`backend/`](backend/). Для локального запуска в web нужны **два терминала**:
один для API, второй для Flutter.

## Требования

- Windows / PowerShell для команд ниже.
- Flutter **3.47.7**, как указано в [`Builder/.fvmrc`](Builder/.fvmrc).
  Команда `flutter` должна быть доступна в `PATH`.
- Python **3.12+** и Chrome.

Android SDK и подключённый телефон для web не требуются.

## 1. Запуск сервера

Откройте первый терминал в корне репозитория. При первом запуске подготовьте
окружение и установите зависимости:

```powershell
Set-Location backend
py -3.12 -m venv .venv
& ./.venv/Scripts/python.exe -m pip install -e .
```

Создайте локальный `.env`, если его ещё нет. Существующие настройки сохранятся:

```powershell
if (-not (Test-Path .env)) {
  Copy-Item .env.example .env
}
```

Запустите API из папки `backend`:

```powershell
& ./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 5001 --reload
```

При следующих запусках достаточно перейти в `backend` и выполнить последнюю
команду. Активация виртуального окружения не нужна.

Дождитесь сообщения `Application startup complete`. Сервер создаёт таблицы
автоматически; база и файлы хранятся по путям из `.env`.

- Состояние API: [http://127.0.0.1:5001/health](http://127.0.0.1:5001/health).
- Документация API: [http://127.0.0.1:5001/docs](http://127.0.0.1:5001/docs).

## 2. Запуск web-приложения

Откройте **второй терминал в корне репозитория**:

```powershell
Set-Location Builder
flutter pub get --enforce-lockfile
flutter run -d chrome --web-hostname 127.0.0.1 --web-port 8080 --dart-define=APP_ENV=dev --dart-define=CRAFTAI_API_BASE_URL=http://127.0.0.1:5001
```

Flutter откроет Chrome. Адрес приложения:
[http://127.0.0.1:8080](http://127.0.0.1:8080).
Оба терминала должны оставаться открытыми.

После установки зависимостей можно повторно запускать только команду
`flutter run`. Если Chrome недоступен, замените `-d chrome` на `-d edge`.

Явный `CRAFTAI_API_BASE_URL=http://127.0.0.1:5001` нужен для подключения к
локальному HTTP-серверу: настройка по умолчанию в debug использует HTTPS.

## 3. Вход

Сервер при старте создаёт локальный аккаунт разработчика:

- Почта: `local-dev@craft-ai.local`
- Пароль: `LocalDevPass123!`

После входа пройдите онбординг, если он предлагается. Основной экран —
«Мои агенты».

Для вызовов реальных моделей задайте в **`backend/.env`** ключ
`CRAFTAI_OPENROUTER_API_KEY` и настройки двух слотов
`CRAFTAI_LAB_MODEL_1_*` / `CRAFTAI_LAB_MODEL_2_*` из
[`.env.example`](backend/.env.example), затем перезапустите API.
При пустых ID модели недоступны для запуска. Ключ провайдера остаётся на сервере;
передавать его через Flutter `--dart-define` не нужно.

В web локальный SQLite-кэш не используется. Агенты сохраняются на сервере,
а локальные черновики могут потеряться при перезагрузке страницы.
Готовность остальных функций отражена в
[плане и прогрессе](docs/plans/01-prd-0-2-mobile-mvp-progress.md).


## Проверки перед PR

Обычные тесты Flutter запускаются без backend (из папки `Builder`):

```powershell
flutter test --reporter expanded
```

Проверка форматирования охватывает также отдельные тесты с живым API:

```powershell
dart format --output=none --set-exit-if-changed lib test test_live
flutter analyze
```

Для сквозной проверки авторизации и API сначала запустите локальный backend
в режиме `CRAFTAI_APP_ENV=dev`, затем из `Builder` выполните:

```powershell
flutter test test_live/live_backend_e2e_test.dart
```

Этот набор создаёт тестового пользователя и использует локальную dev-учётную
запись. По умолчанию он обращается к `http://127.0.0.1:5001`. Другой адрес
задаётся явно: `--dart-define=LIVE_BACKEND_BASE_URL=https://<TEST_SERVER>`.
Для HTTPS требуется доверенный сертификат.

Backend-тесты запускайте из `backend` в отдельном тестовом окружении:

```powershell
& ./.venv/Scripts/python.exe -m pip install -e ".[dev]"
& ./.venv/Scripts/python.exe -m pytest -q
```

Они пересоздают тестовую БД `test_craftai.db` и подменяют провайдера моделей;
живой API и ключ OpenRouter не требуются. GitHub Actions запускает обычные
Flutter-тесты в Builder CI и backend-тесты в Backend CI. Сквозная проверка
с живыми моделями и приёмка на устройстве выполняются отдельно.

## Остановка и частые проблемы

- Остановить Flutter: `q` в его терминале; остановить API: `Ctrl+C`.
- `flutter` не найден: добавьте папку `bin` установленного Flutter в `PATH`
  и откройте новый терминал.
- Нет соединения с API: убедитесь, что первый терминал работает, откройте
  `/health` и проверьте значение `CRAFTAI_API_BASE_URL` в команде Flutter.
- Порт занят: остановите предыдущий запуск. Если меняете порт API, измените
  его и в `--port` сервера, и в `CRAFTAI_API_BASE_URL` приложения.
- После изменения `.env` или `--dart-define` полностью перезапустите
  соответствующий процесс.
