# LM04: несколько агентов в Builder

**Глубина:** L2 · **Статус:** реализация · **Цель:** управление серверными агентами.

## 1. Область
Список, создание с мастером или без него, переименование, копирование,
редактирование инструкции, сброс, удаление. Сервер определяет версии и лимит.
Диалог и настройки инструментов переходят на новый runtime в LM05.

## 2. Оценки
По контракту не более пяти агентов на пользователя. Для пилота из LM01
(20 одновременных пользователей) открытие списка даёт до 20 запросов;
максимальный текст пяти инструкций — около 100 КБ UTF-8.
Пагинация и отдельная служба кэширования не нужны. Таймаут запроса — 20 с.

## 3. Сейчас
Riverpod → один локальный AssistantRepository → SQLite v1.
Авторизация уже использует обновляемые токены; доступны HTTP-клиент,
локальная БД, шифрование StorageCipher и ключ установки в системном хранилище.

## 4. Целевая схема
Экран → AgentsRepository(ownerId) → LabApiClient → /lab/v1/agents.
SQLite v2 хранит зашифрованные снимки, выбранный ID и черновики по
(owner_id, agent_id). Курс остаётся по owner_id, без зависимости от агента.
Кэш используется только для чтения при сетевой ошибке и явно помечается;
мутации доступны после успешной синхронизации. Очереди фоновых записей нет.
После подтверждённой мутации меняется кэш; сброс очищает данные только
целевого агента. Полный список обновляется при открытии и по запросу пользователя.

## 5. Риски
Смена пользователя во время запроса: проверка владельца токенов до и после
HTTP, отдельные провайдеры на ownerId, сброс выбранного ID при выходе.
Повтор create/copy при потере ответа может создать дополнительного агента:
автоповторов POST нет, кнопки блокируются, после ошибки список сверяется заново.
Кэш не считается подтверждением существования агента на сервере.

## 6. Миграция и проверка
Аддитивная миграция v1 → v2, без переноса старых локальных данных к случайному
серверному агенту. Старые агентные таблицы получают nullable agent_id;
новый поток использует только составные ключи v2. Прогресс не удаляется.
Старый глобальный сброс удаляется. Тесты: контракт HTTP, SQLite-миграция,
изоляция владельцев/агентов, перезапуск кэша, действия экрана и лимит.
Содержимое инструкций и токены в журналы не выводятся.

## 7. Открытые вопросы
Ручная проверка после перезапуска зависит от доступности Android-устройства
и работающего сервера. Архитектурную диаграмму можно добавить по запросу.

## 8. Порядок
Контракт и хранилище → провайдеры → список/мастер/карточка → маршруты,
локализация → целевые проверки и обновление прогресса.

## 9. Ручная приёмка на устройстве (ожидается)
1. Подключить телефон и сервер, войти в тестовый аккаунт.
2. В «Мои агенты» создать двух агентов через мастер, изменить итоговую инструкцию.
3. Переименовать первого, скопировать; проверить счётчик и инструкцию копии.
4. Сбросить первого: второй и прогресс курса должны сохраниться.
5. Заполнить пять мест, проверить сообщение о лимите; удалить копию и создать нового.
6. Открыть второго, изменить инструкцию без сохранения; закрыть и заново запустить
   приложение. Проверить список и восстановленный черновик.
7. Отключить сеть, обновить список: сохранённые агенты видны, действия изменения
   недоступны. Вернуть сеть, нажать «Обновить».
8. Выйти и войти под другим пользователем: чужих агентов и черновиков быть не должно.

Сценарий копирования без серверной памяти проверяется API-тестами LM01;
ручная работа с памятью из интерфейса появляется в LM05.
