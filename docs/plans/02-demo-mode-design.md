# Демо без сервера

**Глубина:** L2 · **Статус:** реализация · **Цель:** запустить продукт одной
командой Flutter без регистрации, Python и ключа модели.

## 1. Область
Два учебных агента, CRUD агентов, примеры материалов/памяти/скиллов,
диалог с ответами по шаблону и подтверждением сохранения, просмотр событий.
Реальная генерация, распознавание фото и серверная приёмка в демо не входят.

## 2. Оценки
Один пользователь на вкладку, до пяти агентов, два исходных материала.
Данные ограничены временем жизни страницы, ответ формируется локально.
Сетевых обращений к API и расходов на модель нет.

## 3. Сейчас
AgentsPage → AgentsRepository → LabApiClient → HTTP API.
Экраны lab_runtime принимают API через конструктор и ещё не подключены
к основному роутеру. Эти интерфейсы позволяют повторно использовать экраны.

## 4. Целевая схема
main_demo.dart → отдельный ProviderScope/роутер → штатные экраны → штатные
API-клиенты → DemoHttpClient → память вкладки.
Паттерн: локальный адаптер транспорта, поскольку он сохраняет реальные
форматы запросов и не требует второго сервера. Альтернатива — сидировать БД
сервера — оставила бы установку Python и настройку окружения обязательными.
Каждая вкладка получает отдельное состояние, фиксированного явно демонстрационного
пользователя и две модели с названиями «Демо». Основной main.dart демо не импортирует.

## 5. Риски
Подмена демонстрации реальным ИИ → постоянный баннер и пометка в каждом ответе.
Случайная отправка данных → транспорт не создаёт сетевых соединений.
Копирование/сброс → данные разделены по agent_id, копируется только конфигурация.
Демокод не должен стать обходом авторизации → отдельная точка входа,
запуск в release запрещён. Ответы не подтверждают качество реальной модели.

## 6. Запуск и проверка
`flutter run -t lib/main_demo.dart -d chrome` из Builder.
Обновление страницы восстанавливает исходные примеры. Обычный запуск main.dart
не меняется. По текущему указанию пользователя тестирование отложено;
форматирование, статический анализ и компиляция демо выполняются отдельно.

## 7. Открытые вопросы
Для проверки реального backend остаётся обычный запуск из корневого HOW_TO_RUN.md.
Архитектурная диаграмма доступна по запросу.

## 8. Реализация
Данные и транспорт → демоприложение/переходы → инструкция запуска → анализ/сборка.
