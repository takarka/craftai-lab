# CraftAI Lab

Требования к мобильному MVP

PRD 0.2 • 15 ноября 2026 • Рабочая редакция для проектирования и разработки

### Продуктовое решение

CraftAI Lab — мобильная платформа внутри экосистемы CraftAI для изучения и создания ИИ агентов. Пользователь осваивает устройство агента через уроки и эксперименты, собирает работающего помощника для своей задачи и продолжает пользоваться им после обучения. Формула продукта: обучение + практика = работающий ИИ агент.

Первый сегмент — учителя без обязательных навыков программирования. Первый маршрут — создание агента для подготовки учебных заданий по собственным материалам. После маршрута учитель самостоятельно адаптирует агента к новой теме и создаёт второго агента для другой педагогической задачи.

### Что закреплено в новой версии

Мобильное приложение становится первым клиентом. Педагогические сценарии определяют содержание MVP; структура платформы допускает другие аудитории в дальнейшем. Пользователь может создавать несколько отдельных агентов. Обучение охватывает инструкции, контекст, инструменты, MCP, скиллы, память и harness. Будильник исключён из продукта и плана выпуска.

### Назначение PRD

Документ задаёт границы выпуска, учебный маршрут, требования к мобильному приложению и выполнению агентов, критерии приёмки, проверку пользы и конкурсный пакет. Получатели — владелец продукта, разработчик, дизайнер и методист. PRD заменяет редакцию 0.1; это план, а не подтверждение готовности функций.

### Статус решений

Подтверждено пользователем: мобильный старт, учителя в MVP, обучение через создание агентов, развитие платформы для разных задач, выбор моделей и сервер в Казахстане. Предлагается в PRD: один учебный маршрут, две модели, один управляемый MCP сервер, ограниченный каталог скиллов, объём фото и лимиты пилота. Эти параметры можно уточнить после технической оценки.

### Основания

Источники — согласованная концепция в обсуждении и приложенные требования к MVP Codex Challenge с приложениями А и Б. Основное Положение, приложение 1, срок и официальная инструкция публикации не предоставлены. Внешний рыночный анализ не входит в эту редакцию.

## 1 Аудитория и границы MVP

### Пользователь и проблема

Первый пользователь — учитель, знакомый с обычными ИИ чатами или готовый начать работу с ними. Гипотеза проблемы: он умеет получать отдельные ответы, но затрудняется настроить устойчивого помощника, подключить данные и действия, объяснить ошибку и проверить исправление.

Результат для пользователя — работающий агент для подготовки заданий, собственные проверочные примеры и способность изменить конфигурацию без пошаговой подсказки. Для MVP не требуется знание кода, настройка сервера или самостоятельное получение API ключей.

| Входит в MVP | После проверки MVP |
| --- | --- |
| Один учебный маршрут для учителей и проверка переноса навыка | Маршруты для других профессий и открытый каталог курсов |
| Несколько личных агентов, создание, копирование, запуск и удаление | Публичные агенты, маркетплейс и совместное редактирование |
| Текст, учебный материал из текста или одного фото | Голосовой ввод и голосовой разговор |
| Выбор из двух реально подключённых моделей | Расширенный каталог и сравнительный курс по моделям |
| Один управляемый MCP сервер материалов с поиском и сохранением | Произвольные MCP подключения и внешние действия |
| Два учебных скилла, настройка разрешённого текста и версий | Импорт сторонних скиллов и выполнение пользовательского кода |
| Видимые настройки памяти, трасса действий, лимиты и подтверждения | Фоновое автономное выполнение и взаимодействие нескольких агентов |

### Пределы первой версии

Первая мобильная ОС и поддерживаемые версии выбираются по устройствам пилотной группы до разработки клиента. Русский интерфейс предлагается для первой версии; казахская локализация — отдельное решение. Работа моделей требует сети; офлайн генерация не заявляется. Монетизация и публичный запуск в магазинах не являются условиями учебного пилота.

Многократное создание агентов — принцип продукта. «Бесконечно» не означает отсутствие лимитов: предлагаемый пилот допускает 5 активных агентов на пользователя, удаление освобождает место. Бюджет запусков и файлов показывается отдельно. Агенты изолированы и не обмениваются данными автоматически.

## 2 Учебная модель и содержание курса

Единица обучения: короткое объяснение → прогноз пользователя → одно изменение агента → реальный запуск → сравнение с прогнозом → самостоятельное задание. Нажатие «Далее» само по себе не завершает практику. Улучшение ответа после каждого изменения не гарантируется; неожиданный результат разбирается.

| Урок | Практическое действие | Свидетельство понимания |
| --- | --- | --- |
| 1 Инструкция и модель | Создать агента, задать класс и формат заданий; получить ответ | Объяснить отличие модели от правил агента |
| 2 Контекст и фото | Добавить учебный фрагмент, проверить распознанный текст | Объяснить, какие сведения были переданы в текущий запрос |
| 3 Инструмент и MCP | Сохранить материал через инструмент, найти его в новом диалоге | Показать реальный вызов и объяснить роль MCP подключения |
| 4 Скилл | Включить скилл подготовки заданий, изменить допустимое правило | Отличить инструкцию по работе от доступа к инструменту |
| 5 Память и границы | Сохранить предпочтение по классу, затем удалить его | Объяснить отличие истории, контекста и долгосрочного хранения |
| 6 Harness и проверка | Настроить подтверждение сохранения, увидеть остановку по лимиту | Объяснить последовательность модель → инструмент → результат |
| 7 Перенос навыка | Без пошагового мастера создать второго агента для объяснения темы | Настроить новую задачу и выполнить собственную проверку |

### Операционные определения для продукта

Агент в MVP — сохраняемая конфигурация модели, инструкций, скиллов, разрешённых инструментов и памяти, запускаемая средой выполнения. Он может запросить вызов инструмента, получить результат и продолжить работу в пределах лимитов. Обычный ответ модели без действия не служит доказательством работы инструмента.

MCP — механизм подключения сервера инструментов и данных. Это не сама модель и не обязательный признак любого агента. Скилл в MVP — версионированный набор инструкций для конкретной работы; он не выдаёт разрешения и не выполняет произвольный код. Harness — среда, которая организует контекст, вызовы, ограничения, подтверждения и завершение запуска.

Память в MVP хранится приложением как явно сохранённые сведения и материалы, которые можно найти и включить в контекст. Изменение инструкций, скиллов или памяти не называется дообучением модели.

## 3 Пользовательский путь и мобильный интерфейс

### Первый вход

Пользователь входит способом, предоставленным CraftAI, либо согласованным пилотным доступом. Видит результат курса, пример агента и возможность начать на готовом синтетическом материале. Доступ к камере запрашивается только при выборе фотографии. Отказ не блокирует маршрут с текстом.

### Сборка первого агента

Учитель выбирает задачу «Подготовка заданий», задаёт имя, предмет, класс и требования. Короткие поля формируют видимую редактируемую инструкцию. Модель выбирается из разрешённого списка; поясняется её роль. Полученный ответ оценивается по чек листу.

Далее учитель добавляет материал, включает инструмент, скилл и память по мере уроков. Компоненты становятся доступны после знакомства, затем остаются редактируемыми. В любой момент можно открыть сведения о передаваемых данных, доступах и действующих настройках.

### Дальнейшее использование

В разделе «Мои агенты» пользователь запускает помощника вне урока, копирует результат или отправляет через системное меню «Поделиться». Может создать нового агента, скопировать конфигурацию без истории и памяти, переименовать, сбросить или удалить. Прогресс курса хранится отдельно от агентов.

| Экран | Основное содержание |
| --- | --- |
| Обучение | Маршрут, текущий урок, сохранённый прогресс, итоговая проверка |
| Урок | Короткое объяснение, одно действие, запуск эксперимента, вопрос о результате |
| Мои агенты | Список, задача, последнее использование, создание и копирование |
| Агент | Диалог, вложение, статус запуска и карточка подтверждения действия |
| Настройки агента | Модель, инструкция, материалы, скиллы, память, инструменты и лимиты |
| Как выполнено | Последовательность событий, версия конфигурации, вызовы и ошибки |

### Мобильные ограничения дизайна

Одна основная задача на экран, сохранение черновика при переходах, системное масштабирование текста, подписи для средств чтения с экрана. Ответы до и после показываются переключением между версиями с выделением изменённого параметра; два длинных текста не размещаются в узких колонках.

Для длинной инструкции используются краткие настройки и раскрываемый полный текст. После фонового режима приложение восстанавливает состояние запуска с сервера. Не отправляет сообщение повторно автоматически и не показывает старое состояние как актуальное.

## 4 Функциональные требования к приложению

Приоритет P0 означает обязательное для предлагаемого MVP. Критерии ниже проверяются на реальных вызовах, а не на заранее подготовленных ответах.

| Код | Требование и проверяемый результат |
| --- | --- |
| F01 Аккаунт | P0. Конфигурации, файлы, запуски и прогресс изолированы по владельцу. Проверка: второй пользователь не может читать или менять чужие объекты ни через экран, ни через API. |
| F02 Обучение | P0. Урок хранит версии, инструкцию, действие и проверку. Прогресс сохраняется после перезапуска. Практика завершается по событию и ответу пользователя; итоговое умение отдельно оценивается человеком. |
| F03 Агенты | P0. Можно создать не менее двух агентов, редактировать и переключать их. Копирование переносит только конфигурацию; память, диалоги и доступы к данным не копируются без отдельного выбора. |
| F04 Модели | P0. Две модели реально выполняют запросы. Каталог указывает совместимость с инструментами и фото. Несовместимое сочетание блокируется до отправки; скрытая замена модели запрещена. |
| F05 Материал | P0. Поддержаны вставка текста и одно фото JPEG или PNG до 10 МБ. Распознанный или извлечённый текст можно проверить и исправить. Сервер проверяет реальный тип и лимит файла. |
| F06 Диалог | P0. Доступны отправка, ожидание, остановка и явный повтор. Повтор сетевого запроса не создаёт дубликат сообщения или действия. Сбой показывает причину и возможный следующий шаг. |
| F07 Результат | P0. Готовый ответ можно скопировать или отправить через системное меню. Действуют версии: новая настройка влияет на следующий запуск, старый ответ не переписывается. |
| F08 Сброс | P0. С подтверждением очищаются настройки, память и история выбранного агента и отменяются его запуски. Другие агенты и прогресс курса сохраняются. Поздний ответ не восстанавливает сброшенные данные. |
| F09 Удаление | P0. Удаление агента отличается от сброса и освобождает его лимит. Экран сообщает о последствиях и порядке удаления данных; операция повторяется безопасно без создания побочных объектов. |

### Начальные ограничения пилота

Предлагается: 5 активных агентов на пользователя; 10 000 знаков на учебный фрагмент; 5 000 знаков на инструкцию или скилл. Значения должны быть проверены на выбранных моделях и показаны в интерфейсе. Превышение отклоняется до платного запуска, когда это технически возможно.

## 5 Среда выполнения агента и интеграции

### R01 Реальный цикл выполнения

Мобильный клиент отправляет запрос серверу Lab. Сервер фиксирует версию конфигурации и формирует контекст. Модель возвращает ответ или запрос инструмента. Harness проверяет разрешение и параметры, получает нужное подтверждение, вызывает инструмент и передаёт результат модели. Финальный ответ связан с тем же запуском и его событиями.

### R02 Управляемое MCP подключение

В MVP предлагается один реальный MCP сервер «Материалы» с инструментами save_material и search_materials. Первый сохраняет подтверждённый текст, второй ищет только среди материалов текущего владельца и агента. Адрес сервера и учётные данные задаёт платформа. Пользователь выбирает доступы без ввода ключей.

Приёмка: после сохранения возвращается идентификатор материала; в новом диалоге инструмент находит запись и её идентификатор присутствует в трассе. При отключённом поиске сохранённый фрагмент не добавляется в контекст автоматически. Ответ «я сохранил» без записи в хранилище не считается успехом.

### R03 Скиллы

Начальный каталог: «Подготовка заданий» и «Проверка качества». Видны назначение, текст, версия и действующее состояние. Пользователь включает скилл и меняет разрешённую текстовую часть. Порядок сборки инструкций зафиксирован: правила платформы, инструкция агента, включённые скиллы. Коллизии правил объясняются, ограничения платформы не отменяются.

Текст скилла не создаёт доступ к инструменту. Вызов отключённого инструмента отклоняется средой выполнения. Внешний импорт, скрипты и автоматическая установка зависимостей в MVP не входят.

### R04 Память и разрешения

Материалы и предпочтения сохраняются после явного подтверждения. Пользователь видит и удаляет каждую запись. Удалённая запись не появляется в новых поисках или новом контексте; ранее показанные ответы сохраняются до удаления истории. Поиск разрешается отдельно от записи. Сетевые адреса из учебного материала не выполняются как команды.

### R05 Лимиты и достоверная трасса

Предлагаемые пределы: 3 вызова инструментов и 60 секунд активного выполнения без ожидания пользователя. Подтверждение истекает через 15 минут. При превышении запуск завершается с причиной. Предлагаемое изменение инструмента или данных запрашивает новое подтверждение. Повтор записи защищён ключом идемпотентности; просроченный запрос подтверждения не исполняется.

Панель «Как выполнено» показывает версию инструкции и скиллов, модель, включённые фрагменты, имя и разрешённые параметры инструмента, статус и длительность. Секреты и скрытые рассуждения модели не показываются. При отмене уже выполненное сохранение не отменяется молча: его факт виден и запись можно удалить.

## 6 Данные и технические границы

### Схема и сущности

Первый клиент — мобильное приложение. Сервер Lab обеспечивает авторизацию, хранение конфигураций, выполнение агентов и обращения к моделям и MCP серверу. Предлагаемый независимый API допускает последующее появление других клиентов. Это архитектурное направление, а не требование выбрать конкретный стек.

Основные сущности: пользователь, версия курса, урок, прогресс, агент и его версия, модель, скилл и версия, разрешение, материал, запись памяти, диалог, сообщение, запуск, событие инструмента и подтверждение. Запуск использует снимок конфигурации; изменение настроек не меняет уже выполняемую работу.

### Размещение в Казахстане

Сервер Lab находится в Казахстане — подтверждённое условие концепции. До пилота фиксируются местонахождение базы, файлов, резервных копий, MCP сервера и обработки каждой моделью, а также обработка фото. Размещение сервера само по себе не означает, что данные никогда не передаются за пределы страны. Полностью локальный контур не заявляется без проверки.

| Данные | Правило MVP |
| --- | --- |
| Учебные примеры | В конкурсном пакете только синтетические или обезличенные материалы без данных учеников. |
| Материалы и фото | Перед передачей видны цель и маршрут обработки. Исходное фото предлагается удалять в течение 24 часов после извлечения текста; итоговый срок утвердить до пилота. |
| Агенты и память | Изоляция по владельцу и агенту. Срок хранения активных данных утверждается отдельно; после сброса немедленно закрывается доступ к старой версии. |
| Журналы выполнения | Содержимое доступно владельцу; техническая аналитика хранит статусы, длительность и объём использования без полного текста запросов и файлов. |
| Секреты и удаление | Ключи моделей и интеграций только на сервере. Физическая очистка, резервные копии и удаление аккаунта описываются до допуска реальных пользователей. |

### Обязательные проверки

Сервер проверяет доступ на каждом действии, включая загрузку файла, просмотр запуска, поиск и инструментальную запись. Содержимое фото и материалов рассматривается как данные; оно не расширяет разрешения. Восстановление после сбоя не повторяет запись без проверки её результата.

До пилота требуется журнал фактических расходов на модель и инструмент, лимит бюджета и понятная остановка при исчерпании. Численные сроки очистки и маршруты обработки — блокирующие решения, а не обещания этой версии PRD.

## 7 Надёжность и мобильные состояния

| Ситуация | Ожидаемое поведение |

| Ошибка модели | Явная ошибка и повтор по действию пользователя. Смена модели предлагается открыто и фиксируется в новом запуске. |
| Ошибка инструмента | Модель получает ошибку инструмента, пользователь видит, что действие не подтверждено. Запрещено отображать сохранение как успешное. |

### Предлагаемые цели производительности

При 20 одновременных пользователях: сохранение настроек до 2 секунд для 95% операций; первый фрагмент текстового ответа до 8 секунд для 95% валидных запросов; активное выполнение ограничено 60 секундами без ожидания подтверждения. Загрузка фото и извлечение текста измеряются отдельно. Это стартовые цели для измерения, а не подтверждённые характеристики.

### Доступность и качество интерфейса

Проверить экранную клавиатуру, масштабирование текста, чтение основных элементов средствами доступности, отображение ошибок и сохранение черновиков на реальных устройствах. Важные состояния обозначаются текстом, а не только цветом. Длинный ответ читается без горизонтальной прокрутки.

### Контроль курса и затрат

В пилоте уроки и каталог интеграций может обновлять разработчик через конфигурацию; административный редактор не обязателен. Обновление курса не стирает достигнутый прогресс без объяснения. Тарифы, лимиты и стоимость дополнительных действий должны быть понятны до платного расширения.

### Готовность к распространению

До выбора способа распространения определить ОС, устройства, тестовую сборку, способ установки и предоставление проверочного доступа. Требования магазинов и региональные условия проверяются перед публикацией. Наличие мобильной сборки не заменяет конкурсную публикацию в ChatGPT Edu.

## 8 Приёмка основного сценария

### T01 Учитель собирает и проверяет агента

Предусловия: тестовая сборка установлена, доступ предоставлен, модели и MCP сервер доступны. Данные синтетические. План ниже — инструкция до 10 шагов; фактические названия элементов уточняются в готовом продукте.

1. Открыть конкурсный объект в указанном workspace и следовать согласованной инструкции запуска мобильной версии. Войти предоставленным способом.

2. Начать маршрут «Агент для подготовки заданий», создать агента «Естествознание 5» и выбрать первую модель.

3. Задать правило: «Готовь ровно три нумерованных вопроса для пятого класса. Используй учебный материал. Не добавляй ответы».

4. Добавить текст: «Испарение — переход жидкости в газ с её поверхности. Оно происходит при разных температурах. При нагревании испарение обычно ускоряется». Выполнить запрос «Подготовь вопросы по материалу».

5. Подключить MCP инструменты материалов. Попросить сохранить фрагмент с названием «Испарение». Подтвердить запись и увидеть её идентификатор.

6. Открыть новый диалог без вручную добавленного фрагмента. Попросить найти материал «Испарение» и подготовить вопросы. Проверить реальный поиск в панели выполнения.

7. Включить скилл «Подготовка заданий», изменить правило на два вопроса с краткими ответами. Повторить запуск и оценить результат по чек листу.

8. Сохранить предпочтение «пятый класс», затем удалить его. Убедиться, что запись отсутствует в новом контексте. Перезапустить приложение и проверить сохранение агента.

9. Без пошаговых подсказок создать второго агента для объяснения новой темы. Выбрать вторую модель, задать правила и выполнить собственный проверочный пример.

10. Сбросить первого агента с подтверждением. Убедиться, что второй агент и учебный прогресс сохранены. Записать фактический результат теста.

### Критерии результата

Созданы два отдельных агента; обе модели вызваны реально; запись и поиск подтверждены состоянием хранилища и событиями MCP. Первый набор содержит три вопроса без ответов, изменённый — два с краткими ответами. Методист проверяет четыре критерия: соответствие материалу, отсутствие фактических ошибок, пригодность для класса и соблюдение формата. Дословное совпадение ответов не требуется.

Учитель объясняет различие модели, инструкции, скилла и инструмента; на новой задаче самостоятельно выбирает нужное изменение. На дату PRD тест не выполнен. Перед сдачей заполнить версию, дату, проверяющего, входные данные, фактические результаты, вывод и дефекты. Ожидаемый результат не заменяет запись выполненного теста.
